# container-detail

## Purpose
在容器页点一行之后右侧那块详情区:它把 `wslc` 报出的字段全摆出来,卡片宽度只跟视口走、
不跟数据走。行上那三颗键与操作互斥在 `container-actions.md`(CA),「日志」页签在
`container-logs.md`(LG)。几何与页签为什么这么做的依据见 `docs/notes/winui-shell.md`。

### Requirement: 点一行 = 打开它的详情
一行都没选中时右侧只给一句引导话;选中之后标题与状态立刻出来。

#### Scenario: CD-001 还没选容器时右侧只有一句引导
- **WHEN** 进入「容器」页,一行都没点
- **THEN** 右侧读得到"点击左侧的容器查看详情"
- **AND** 这一侧读不到任何字段名、也没有操作键

#### Scenario: CD-002 点一行就把标题与状态摆出来
- **WHEN** 点左侧任一行
- **THEN** 右侧头部读得到那个容器的名称
- **AND** 名称旁边贴着状态徽标:"运行中"或"已停止",与左侧那行的状态点同一档
- **AND** 头部右端读得到启动 / 停止 / 重启 / 删除这四颗键

#### Scenario: CD-003 换一行,详情立刻跟着换
- **WHEN** 选中另一行
- **THEN** 右侧整块换成新选中那个容器的内容,不留上一条的名字或字段值

#### Scenario: CD-004 行末那颗键也打得开同一个详情
- **WHEN** 点某一行末尾那颗悬停写着"查看详情"的键
- **THEN** 打开的就是这一行那个容器的详情,与直接点这一行的结果一致

#### Scenario: CD-005 自动刷新不许把选中项冲掉
- **WHEN** 选中某一行后,列表被自动刷新过好几轮(容器还在)
- **THEN** 左侧仍是这一行处于选中态,右侧详情不清空、不跳回引导语
- **AND** 详情里的字段跟着最新数据更新(如状态从"运行中"变"已停止")

#### Scenario: CD-021 选中的容器在别处被删掉了
- **WHEN** 详情正开着某个容器,这个容器在别处(另一个终端或本应用)被删除
- **THEN** 右侧读得到"未找到该容器,可能已被删除。"
- **AND** 界面不崩,左侧列表里这一行已经没了

### Requirement: 字段一个都不落在列表里
行上只留名称、状态、镜像(`container-list.md` 的 CL-002),其余全在这块详情里给全。
字段来自 `wslc list -a --format json`,形态与含义见 `docs/notes/wslc-cli.md`。

#### Scenario: CD-006 详情分成这几节
- **WHEN** 选中一个容器,停在「详情」页签
- **THEN** 从上到下读得到「基本信息」「运行状态」「网络」「标签」四节标题

#### Scenario: CD-007 基本信息六项都在
- **WHEN** 看「基本信息」
- **THEN** 读得到 ID、镜像、命令、创建时间、平台、大小这六个标签及各自的值

#### Scenario: CD-008 运行状态三项都在
- **WHEN** 看「运行状态」
- **THEN** 读得到状态、状态详情、健康检查这三级标签及各自的值

#### Scenario: CD-009 网络两项都在
- **WHEN** 看「网络」
- **THEN** 读得到端口与网络两项及各自的值

#### Scenario: CD-010 没有值的字段摆成横杠,不留空白
- **WHEN** 某个容器没有端口映射、没有网络、没有大小、没有健康检查或平台信息
- **THEN** 对应那一项的值读得到"—",不是空着让人以为渲染坏了

#### Scenario: CD-011 详情里的文字选得中
- **WHEN** 用鼠标选中详情里的 ID、镜像、命令或标签值
- **THEN** 能选中并复制出来(整块文本框不是图片,也不截断成看不全的一小截)

#### Scenario: CD-012 切走再回来还在原地
- **WHEN** 从「详情」切到「日志」再切回「详情」,之前已经把内容滚到中间
- **THEN** 详情内容还在,滚动位置没被重置回顶部

### Requirement: 标签那一长串拆得开
`wslc` 把 Labels 报成一整条逗号拼接的串,详情里要按"键一行、值一行"摆;
这条串本身有歧义,依据见 `docs/notes/wslc-cli.md`。

#### Scenario: CD-013 一个标签占两行
- **WHEN** 某容器带着形如 `com.example.a=1,com.example.b=2` 的标签
- **THEN** 「标签」这一节里每个标签各占一组:先一行键名、紧接一行值
- **AND** 两组之间分得清,不挤成一整行

#### Scenario: CD-014 值里带逗号或括号不算拆行
- **WHEN** 某个标签的值里写着带引号或带括号的逗号(例如 `desc="a, b"`)
- **THEN** 这串值仍完整落在它自己那一行,没被从中间拆开

#### Scenario: CD-015 有歧义的值宁可多拆一条,也不丢内容
- **WHEN** 某个标签的值里写了 `,foo=bar` 这种看起来像下一个键的东西
- **THEN** 这条值可能被多拆成一个额外条目,但原文一个字都不少
- **AND** 界面不崩、不报错

#### Scenario: CD-016 一个标签都没有时给横杠
- **WHEN** 选中的容器没有任何标签
- **THEN** 「标签」这一节读得到一个"—",不是一大片空白

### Requirement: 卡片宽度跟着视口,不跟着数据
这块详情曾经"忽宽忽窄、还常偏右":呈现器按内容自己的期望宽度摆放,标签短就明显窄、
长 JSON 就顶到封顶。现在面板宽度直接绑在可视宽度上,依据见 `docs/notes/winui-shell.md`。

#### Scenario: CD-017 卡片拿到整个可视宽,封顶一条线
- **WHEN** 选中任意容器,窗口宽 1180 左右
- **THEN** 详情卡片的宽度等于详情区可视宽度,最宽不超过 600 DIP,并在这一侧水平居中
- **AND** 左右两侧的留白对称

#### Scenario: CD-018 内容极短也不缩窄
- **WHEN** 选中的容器字段都很短(名称、镜像、端口都只有一小截)
- **THEN** 卡片宽度不变,不会因为内容短就缩成一条,也不偏到右边去

#### Scenario: CD-019 内容极长也不撑宽
- **WHEN** 选中的容器带着很长的命令、整段 JSON 的标签值或一长串端口映射
- **THEN** 卡片宽度仍是那一档封顶,长内容在卡片里换行
- **AND** 详情区只竖向能滚,横向滚不动(也不会出现横向滚动条)

#### Scenario: CD-020 窗口变宽,卡片跟着变到封顶为止
- **WHEN** 把窗口从窄拖到宽,停在同一个容器的详情上
- **THEN** 卡片跟着可视宽度一起变宽,到了封顶宽度就不再变,始终居中

### Requirement: 这块区域只有两个页签
「详情」与「日志」是固定两项,不能新建也不能关闭。为什么不用量化的页签控件、
自建页签的视觉态为什么要成对写,见 `docs/notes/winui-shell.md`。

#### Scenario: CD-022 页签条上只有「详情」与「日志」
- **WHEN** 选中一个容器,看详情区顶部那一行页签
- **THEN** 只读得到「详情」「日志」两项,当前所在那一项带下划线,另一项不带
- **AND** 页签条上没有任何"新建标签"那类多余的键
- **AND** 点另一项就切过去,右侧内容整块跟着换(日志那一侧的表现见 `container-logs.md`)
