# 功能 011 · 拉取镜像的实时进度(伪终端屏幕 + 分层汇总)

状态:已完成(2026-10-13,含真机验证)
相关:功能 004(拉取 / 删除编排)、功能 005(日志区的只读等宽文本框与滚动)、功能 010(镜像源改写)

## 是什么

点"拉取"之后,原来只有一个转圈和一句"正在拉取 … · 已等待 N 秒",
现在多了两样东西:

- **分层进度区**:wslc 自己在终端里画的那张"屏幕"原样搬上来 —— 一行代表一个分层的最新状态
  (`Pulling fs layer` / `Downloading 532.5kB` / `Verifying Checksum` / `Download complete` /
  `Extracting 5.5MB/27MB` / `Pull complete`),只读、等宽、可以整块复制,框内自动滚到最新一行;
- **一句话汇总**:同一行进度旁边显示"已下载 1.2 MB · 完成 3/8 层",数字随刷新增长。

做到这件事的办法是把子进程挂进 Windows 伪终端(ConPTY):wslc 认为自己面对真实终端,
进度就**边产生边写出来**,应用从管道另一侧读这些字节,还原成屏幕上的行,再解析成汇总数字。
伪终端起不来时自动退回原来的普通管道路径,拉取结果一模一样,只是中途没有实时进度。

## 为什么

`wslc pull` 在普通重定向管道下**不会**逐行输出:实测 45 行进度全憋在进程退出那一刻一次性冲刷
(开发笔记 #27 记的就是这件事)。所以功能 004 当时只能退而求其次报"已等待几秒"。
而拉取慢的时候(今天实测 60 秒起步、偶尔一直卡在 `Pulling fs layer`)用户看到的确实只是一个转圈,
完全无从判断"是在下载、在解压、还是已经死了",只能凭感觉等或者取消。

分层进度本身 wslc 已经算好了 —— 它只是没往非终端的输出里写。用 ConPTY 骗过它的"我在不在终端里"这个判断,
就能拿到和用户在 PowerShell 里手敲 `wslc pull` 看到的同一张屏幕,不用应用自己猜百分比。

## 实测到的行为(本规格的依据)

| 主题 | 实测结论 |
|---|---|
| 非终端下不流式 | 普通重定向管道:`wslc pull` 到进程退出才一次性冲刷全部行;ConPTY:3–5 秒出第一帧,之后按 wslc 自己的节奏(~15–20 秒一次)原地刷新分层行。这就是本功能存在的唯一理由 |
| 进度是"原地回写" | 每个分层固定占一行,wslc 用绝对定位(CUP)+ 擦除(ED/ECH)把新状态盖在同一行上,不是无限追加。所以必须维护一个屏幕模型(`VtScreenTracker`),按"读到第几行"来算是错的 |
| 分层行形态 | `<12位以上十六进制>: <状态>`;字节写作 `544.5kB` / `1.073MB` / `2.14GB`(**1000 进制**,小数位会变),解压阶段写作 `Extracting 5.5MB/27MB`(分母是这一层的全量)。`24.04: Pulling from library/ubuntu` 是头行,`Digest:` / `Status:` / 完整引用是收尾三行,都不算层 |
| 终态只有两种 | `Pull complete` 和 `Already exists` 才算一层完成;`Download complete` 只是下载完了、还没解压,`Verifying Checksum` 是瞬时事件且不带字节 |
| `Download complete` 不再报字节 | **真机坑**:某层进入 `Download complete` 后那一行不再带字节数。只按当前帧求和的话,"已下载"会从 1.6 MB 退回 545.6 kB 甚至归零 —— 界面上数字倒退比不显示更糟。所以每层记历史最大值(台账),总量只增不减 |
| 父进程标准句柄会盖掉伪控制台 | `CreateProcess` 把父进程当时的 STD_INPUT/STD_OUTPUT/STD_ERROR 句柄继承给子进程,优先级高于 `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE`。从管道/测试宿主里起进程时,子进程根本没挂上 ConPTY,伪终端一帧都收不到(表现就是"只有转圈")。修法:调用前后临时把这三个句柄置零再还原(开发笔记 #29) |
| 提前关输入写端 = 广播 Ctrl+C | ConPTY 在输入写端全部关闭时向子进程广播 Ctrl+C,wslc 一帧不画就带着 `0xC000013A` 退场。输入写端必须一直开着,直到真的取消或结束(开发笔记 #28) |
| stdout 与 stderr 合成一路 | 伪终端里两者不分家:整块屏幕当 stdout 交给 `WslcPullLog` 解析(`Status:` 行还在里面);错误横幅只取"不是分层进度"的那些行,否则几十行 `Downloading…` 会把真正的报错淹没 |
| 重复拉已存在的镜像 | 全程 ~2 秒,屏幕只有头行与 `Already exists` / 收尾三行,没有字节数 —— 汇总行这时不该占位 |
| 取消 | 按整树终止 `wslc` 进程,面板当场收起、提示"已取消拉取 …";`wslc images` 里没有半截镜像,本机也没有残留的 `wslc` 进程 |
| 网络差的时候 | 一个层可以几十秒停在 `Pulling fs layer`、"已下载 0 B"(今天 debian:12-slim 实测 54 秒后才开始报字节)。百分比这时候确实算不出来,但"卡在哪一层、已经等了多久"本身就是能用的反馈 |
| 界面刷新次数 | 一帧里 wslc 会连着写好几个转义块;内容与上一次完全相同的帧直接丢掉,不然界面会白抖 |

## 预期行为(验收条件)

### AC1 · 拉取经伪终端执行,命令映射不变
`ImagesService.PullWithProgressAsync(reference, onVisibleLines, ct)` 仍然只执行 `wslc pull <引用>`,
参数与功能 004/010 用的完全一致(不额外 `-q`、不重复跑第二遍)。
`ConPtySession.TryStart` 失败时退回 `RunAsync` 普通管道路径,结束时把全部行一次性交给同一个回调 ——
**降级只影响"中途有没有反馈",不影响拉取结果**。

### AC2 · 汇总一句话:已下载量 + 完成层数
`WslcPullProgress.Parse(lines, ledger)` 从屏幕行算出:

- `TotalLayers` = 见过的分层数(头行 / `Digest:` / `Status:` / 引用行都不算);
- `DoneLayers` = 状态以 `Pull complete` 或 `Already exists` 开头的层数;
- `DownloadedBytes` = 每层历史最大字节数之和 —— **单调不减**,某层不再报字节数也仍然算在里面;
- 字节按 1000 进制格式化成 `544.5 kB` / `1.1 MB` / `2.1 GB`,与 wslc 自己的写法同风格。

层数为 0(manifest 还没拿到)时汇总为空串,界面上这一行不占位置。

### AC3 · 分层进度原样上屏
`PullProgressText` 一行 = 一个分层的最新状态,行数只随层数增长、不随刷新次数变长;
用 CRLF 拼接(只读文本框认 CRLF,与日志区同一套做法)。区域等宽字体、只读、可整块复制、
最高 160 DIP,超出后框内滚动并自动滚到最新一行(与功能 005 共用 `TextBoxScroller`)。

### AC4 · 结束就收起,不留半截
成功、失败、取消三种收场都把进度区与汇总一起收起来,剩下结果提示和新列表(沿用功能 004/010 的行为)。
失败时错误横幅里是"不是分层进度"的那些行,真正的报错不会被几十行 `Downloading…` 淹没。

### AC5 · 取消与互斥语义不变
取消仍然整树杀掉 `wslc`(不留挂死的后台读线程);取消必须报成"已取消",不能被报成命令失败。
全局单操作互斥(功能 004 · AC5)与"拉取后改名"(功能 010 · AC5)都不受影响。

### AC6 · 上一次的残留不能跟着下一次拉取跑
开始一次新操作时清掉三样东西:进度行、去重用的"上一次推送"、以及每层字节台账。
少了第三条,第二趟拉取的"已下载"会从上一趟的数字接着往上涨。

### AC7 · 中英双语
新增文案键 `pull.summary`("已下载 {0} · 完成 {1}/{2} 层")与 `pull.progress.tooltip`,
中英两套键集合完全一致、占位符一致(由 `LocalizerTests` 钉住)。

### AC8 · 不碰既有约定
`IWslcCli` 加一个 `RunWithConsoleAsync`,`UnavailableWslcCli`(没装 wslc 时)给出同签名的占位实现;
`PullAsync` / `RunAsync` / `RunLinesAsync` 的语义与既有断言原样保留;
日志页的"滚到最新一行"抽成公共类,行为不变。

## 已知边界

- **刷新节奏由 wslc 决定**:实测 ~15–20 秒一帧,应用不额外造"假进度"。想更细的百分比得 wslc 自己给总字节数,
  目前它只给"这一层目前下了多少"。
- **层数为 0 时不显示汇总**:刚点下拉取、manifest 还没回来,那一刻只有"正在拉取 … · 已等待 N 秒"。
- **"已下载"是各层"见过的最大字节数"之和(只增不减),不是流量统计**:解压阶段 `Extracting 5.5MB/27MB` 里的分母会被当成这一层的全量计入,
  跨层的平均值、速率这类需要时间序列的东西本功能不做。
- **伪终端里 stdout / stderr 合成一路**:错误横幅靠"去掉分层进度行"来提纯,极端情况下如果报错信息长得像分层行
  (`<十六进制>: …`)会被滤掉,但整块屏幕仍然照常进 stdout 参与结果解析。
- **ConPTY 起不来时静默降级**:理论上只有 Windows 10 1809 以前或被安全软件拦住 conhost 才会发生,
  行为退回功能 004 的样子(结束时一次性给出全部输出),不弹错误框。
- **不覆盖 `wslc build` 之类其他长命令**:这一版只把 `pull` 接进伪终端,`VtScreenTracker` / `ConPtySession` 是通用的,
  以后要给别的长命令加实时进度可以直接复用。
