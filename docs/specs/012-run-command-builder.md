# 功能 012 · wslc run 命令可视化编排(生成 / 复制 / 就地执行 / 粘贴读回)

状态:已完成(2026-10-14,含真机验证)
相关:功能 001 / 002(容器列表与容器操作)、功能 003 / 004(镜像与拉取)、功能 009(中英双语文案)、功能 010(镜像源完整引用)

## 是什么

侧栏多一页「命令编排」。左边是一张表单,把 `wslc run` 常用的选项摊成能点的控件:

- **基本信息**:镜像(唯一必填)、容器名称、后台运行 / 自动删除 / 交互 / 分配伪终端 / 发布全部端口、拉取策略(默认 · always · missing · never);
- **初始化命令**:覆盖入口 `--entrypoint`、命令与参数;
- **端口映射**:可加任意多行,每行「绑定 IP(可选)· 主机端口 · 容器端口 · tcp/udp」;
- **文件系统**:挂载行(来源 / 容器路径 / 只读)、tmpfs 路径行;
- **环境变量与文件**:变量行(键 / 值)与 `--env-file`;标签行(键 / 值);
- **网络与资源**:主机名、网络、CPU 数、内存上限、共享内存;
- **工作环境**:工作目录 `-w`、用户 `-u`;
- **健康检查**:检查命令、间隔、超时、重试次数、启动宽限、以及"不做健康检查";
- **其他参数**:原样透传的长尾选项(例如 `--gpus all --dns 8.8.8.8`)。

右边那条命令**边填边长出来**,顶上写着"还差什么"。三个动作:

| 动作 | 干什么 |
|---|---|
| 复制 | 把界面上这条命令写进剪贴板,拿去终端粘 |
| 粘贴并编辑 | 读剪贴板里的 `wslc run` 命令,把表单按它填好,继续在这里改 |
| 就地执行 | 不离开界面直接起容器,输出落在下面的框里;运行中可以终止 |

表单状态本身是一个 `RunSpec`,拼装 / 校验 / 反向解析全在 `RunCommandBuilder`,页面层只管呈现与剪贴板。

## 为什么

`wslc run` 一条命令动辄七八个选项,端口、挂载、环境变量还是可重复的。在终端里手敲有三个实际成本:
拼错 `-p` 的格式要等容器起不来才发现;想换个端口就得从头再敲一遍;
上一条命令躺在历史记录里,想复用只能翻历史再改,改坏了还看不出来。

所以把"写命令"变成"填表 + 一眼看到结果":命令就在右边摆着,改哪个字段它动哪一段,
复制走和就地执行用的是同一条,不存在"预览一个、执行另一个"两副面孔。

## 实测到的行为(本规格的依据)

| 主题 | 实测结论 |
|---|---|
| 选项集合对得上 | `wslc run --help` 列出的"带值选项"全集与 `RunCommandBuilder.ValueFlags` 一致(含 `-e/-l/-m/-p/-u/-v/-w/-h` 的短形式与长形式别名) |
| 命令别名 | `wslc run` 与 `wslc container run` 都接受,读回时两种前缀都认 |
| `--pull` 的默认 | 真实默认是 `missing`。界面里的"默认"= **不下发这个选项**,让 wslc 自己的默认生效,而不是替用户写死一个 |
| `-d` 的输出 | 只有一行 64 位容器 ID(`wslc run -d --rm --name wslcd-012-smoke -p 18080:80 docker.1ms.run/library/nginx` 实测) |
| `--rm` | 容器停下即删除,`wslc list -a` 里查不到这个 name,不需要应用补刀清理 |
| 裸镜像名 ≠ 本机镜像 | 本机镜像带着 `docker.1ms.run/library/` 前缀,敲 `nginx` 会解析到 docker.io 并去拉取,网络差时直接 `context deadline exceeded` / `E_FAIL` 失败。因此候选列表一律用 `wslc images` 的**完整引用**,不猜短名 |
| 空行不参与拼装 | 加了一行没填 = 视同不存在,不会留下空的 `-p` / `-v` / `-e` |
| `-w` / `-u` 曾经漏发 | `Build()` 没输出工作目录与用户,界面填了却静默丢弃(TryParse 还会把它们读回来,一来一回更难发现)。已补进拼装顺序并加回归用例 |
| 样式贴错类型会当场崩 | 端口行的协议下拉框误贴了文本框样式 → 点「添加端口」时 `XamlParseException`,整个应用退出(0xc000027b),而编译、打开页面、跑单测全都正常。已加静态闸与开发笔记 #37 |
| 剪贴板占用被误报成失败 | `Clipboard.Flush()` 抛 `0x800401D0`(别的进程正开着剪贴板)时内容其实已经可粘。改为重试 + 回读确认,开发笔记 #38 |
| 下拉框选框空着 | 「拉取策略」用内联 ComboBoxItem + 绑定内容时,序号已选中但框里没字(点开列表一次才有);候选项换成纯字符串即好。已加静态闸与开发笔记 #39 |

## 预期行为(验收条件)

### AC1 · 生成与执行同源
界面上显示的 `GeneratedCommand` 与真正交给 `wslc` 的参数数组出自同一份 `RunSpec`:
`Display` 分词后逐 token 等于 `Build()`(引号解码后比对)。复制走的那条 = 就地执行的那条。

### AC2 · 拼装顺序固定
`run` → 开关(`-d -i -t --rm -P`)→ `--pull --name -h --network --cpus -m --shm-size -w -u` →
`-e`… → `--env-file` → `-l`… → `-p`… → `--entrypoint` → `--tmpfs`… → `-v`… →
健康检查选项 → `--no-healthcheck` → 其他参数 → 镜像 → 命令 → 参数。
同样一张表单项填得再乱,命令长相恒定,便于肉眼比对与 diff。

### AC3 · 留空即不下发
除"后台运行"默认为勾上之外,任何字段留空都不输出对应选项;整行留空跳过该行。

### AC4 · 校验先放行、再执行
`Validate` 逐行给问题与行号(镜像为空 / 端口缺容器侧 / 端口号非法 / 端口范围跨度不等 / 协议非 tcp-udp /
挂载缺来源或缺目标 / tmpfs 空 / 变量键空 / 标签键空 / 重试次数非整数 / CPU 数非数字)。
有问题时**复制与就地执行都不放行**,顶上一次性列全,不等到执行时才报错。

### AC5 · 端口行的边界
`[绑定IP:]主机端口:容器端口[/协议]`;范围 `8000-8010:80-90` 只有两侧跨度相等才放行,`8000-8010:80` 报"范围";
`0` / `70000` / `abc` / `90-80` 报端口号并把用户填的原值回显在提示里;协议 tcp/udp 二选一。

### AC6 · 反向解析与往返
`TryParse` 接受 `wslc run …` / `wslc.exe run …` / 绝对路径的 `wslc.exe` / `wslc container run …`;
拒绝 `docker run …`、裸 `wslc`、`wslc ps`。认得的选项落回表单,认不出的选项连同取值整段进"其他参数"
(如 `--gpus all`、`--dns 8.8.8.8`、`--ulimit`、`--pull` 的非三个标准值)。
Windows 盘符带冒号(`C:\data:/app:ro`)、带空格的值(引号包住)都要能读回来;
`Display → TryParse → Display` 结果不变。

### AC7 · 就地执行
默认后台运行,秒回容器 ID 并提示"可到「容器」页查看";取消勾选后台运行则容器的输出逐行实时落到输出框。
运行中可终止:只终止本应用起的 `wslc` 进程,提示"已终止 wslc 进程",执行期间禁止重复触发。
失败时把 wslc 的报错原样呈现(去掉 wslc 自带的那句"如果此错误是意外错误…"套话),不让用户只看见一个"失败"。

### AC8 · 复制真的复制得上
点复制后剪贴板内容就是界面上那条;剪贴板被别的进程占用时重试并回读确认,不把已经成功的复制报成失败。

### AC9 · 读回表单
「粘贴并编辑」把剪贴板里的 `wslc run` 命令摊回表单 —— 逐属性搬到现有 `Spec` 上(页面的绑定与监听都挂在
同一个对象上),右边那条命令立刻跟着变,提示"已从剪贴板读回命令"。剪贴板里没有文本、或者读不懂
(不是 `wslc run` 命令)各有各的提示,并且**不动**用户已经填好的表单。

### AC10 · 镜像候选只是辅助
进入页面时用 `wslc images` 的完整引用填候选,可直接选;取不到(未装 wslc、命令失败)就留空,手打不受影响。

### AC11 · 双语与导航
`run.*` 文案在中英两套键集合一致(由 `LocalizerTests` 钉住);侧栏「命令编排」用 Segoe MDL2 的 `E756`。

### AC12 · 不破坏既有分层
`RunSpec` / `RunCommandBuilder` / `RunBuilderPageViewModel` 全在 Core,不引用任何 WinUI 类型;
剪贴板、进程调度只出现在页面层。`ContainersService.RunAsync` 只是把参数数组交给既有的 `RunLinesAsync`,
不新增第二套起容器的路径。

## 补强(2026-10-15)· 一键清空与就地执行历史

### AC13 · 一键清空
「清空」按钮把整张表单一次性回到初始状态(后台运行仍勾着):逐属性搬到一份全新 `RunSpec` 上,
行集合、输出面板、错误/成功提示一并抹平。执行进行中不放行(与终止按钮同一 busy 判断)。

### AC14 · 就地执行历史(最近 100 条,可恢复)
按下「就地执行」即把当时生成的那条命令记入历史(不问成败 —— 跑失败了更要能找回),最新在前,
连续同一条命令只记一次,超出 100 条挤掉最旧的。每条历史显示时刻 + 命令原文,点「恢复」走与
剪贴板读回同一条 `TryParse → ApplyParsed` 路径填回表单;执行中点恢复只给提示不改表单。
历史是会话级的:`RunHistory` 实例挂在 `AppServices`,切语言重建页面不丢,应用退出即清空 ——
它救的是"这条没跑对,我要接着改"的工作现场,不是档案。

## 已知边界

- **只管 `wslc run`**:compose、多容器编排、`wslc build` 之类不在本功能范围。
- **长尾选项不逐个建控件**:`--mount`、`--ip`、`--cidfile`、`--network-alias`、`--stop-signal` 等
  只走"其他参数"原样透传,应用不校验它们的取值格式 —— 有独立输入框的那几个选项才做逐项校验。
- **校验只到客户端这一层**:端口号、必填、整数这类能当场判定的会拦住;
  路径不存在、端口被占用、镜像拉不下来这些要 wslc 才知道的,照它的报错原文呈现。
- **取消只终止 wslc 进程**:前台运行中点终止是杀掉本应用起的 `wslc`,容器若已经起来由 wslc 侧接管,
  要停容器请去「容器」页 —— 本功能不假装能替用户"顺手把容器也停掉"。
- **输出框是纯文本**:不分色、不解析 JSON,只保证"看得见 wslc 写了什么"和"滚到最新一行"。
- **就地执行历史只活一个会话**:记最近 100 条、恢复回表单(见"补强"),但不落盘 —— 应用重启后清空;
  跨会话复用仍走剪贴板。
