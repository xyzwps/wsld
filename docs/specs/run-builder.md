# run-builder

## Purpose
「命令编排」页左边那张表单:把 `wslc run` 的常用选项摊成能填能勾的控件,右边一条命令
边填边长出来,「复制」拿去终端跑、「就地执行」直接起容器、「粘贴并编辑」把现成的命令读回来接着改。
这本册子锁这一屏:命令同源、校验闸门、读回与执行历史。侧栏那一项的呈现归 `shell.md`,
中英两套键集合一致归 `i18n.md`;容器起来之后的事归 `container-list.md` 与 `container-actions.md`。
实测到的 wslc 行为与刻意的取舍写在 `docs/notes/run-command.md`,坑的来历见 `docs/dev-notes.md` 第 35、37、38、39 条。

### Requirement: 命令边填边长,复制走的就是就地执行的那条
界面上显示的一条、写进剪贴板的一条、真正交给 `wslc` 的一条是同一条;拼装顺序固定,
同样一张表填得再乱,命令长相恒定,便于肉眼比对与 diff(依据见 `docs/notes/run-command.md`)。

#### Scenario: RB-001 进页面第一眼就有一条命令
- **WHEN** 首次进入本页,任何字段都没动
- **THEN** 「生成命令」处读得到 `wslc run -d`
- **AND** 满页的勾选里只有「后台运行 (-d)」默认是勾着的

#### Scenario: RB-002 改哪个字段,命令就动哪一段
- **WHEN** 填了镜像之后,取消勾选「后台运行 (-d)」,再在「容器名称 (--name)」里写 web
- **THEN** 命令里 `-d` 消失、`--name web` 出现
- **AND** 全程不需要点任何"生成"之类的键,改一下动一下

#### Scenario: RB-003 显示的一条与交给 wslc 的一条逐段一致
- **WHEN** 填好表单,先「复制」,再用「就地执行」跑同一条
- **THEN** 真正交给 `wslc` 的参数与界面上那条命令分词后逐段相同
- **AND** 剪贴板里拿到的也是这一条,不存在"预览一个、执行另一个"两副面孔

#### Scenario: RB-004 填表顺序不动命令长相
- **WHEN** 同样一批值,一次先填端口和挂载再填镜像与名称,另一次倒着填
- **THEN** 两次生成的命令逐字相同

#### Scenario: RB-005 固定顺序可以拿一条样例核对
- **WHEN** 填上:后台运行、`--rm`、拉取策略 always、名称 web、工作目录 `/srv`、用户 `1000:1000`、变量 `TZ=Asia/Shanghai`、端口行 `18080:80/udp`、挂载行 data→/app 勾只读、其他参数 `--dns 8.8.8.8`、镜像 docker.1ms.run/library/nginx、命令 nginx
- **THEN** 命令逐字读作 `wslc run -d --rm --pull always --name web -w /srv -u 1000:1000 -e TZ=Asia/Shanghai -p 18080:80/udp -v data:/app:ro --dns 8.8.8.8 docker.1ms.run/library/nginx nginx`
- **AND** 顺序恒为:开关(-d -i -t --rm -P)→ `--pull --name -h --network --cpus -m --shm-size -w -u` → `-e`/`--env-file`/`-l` → `-p` → `--entrypoint` → `--tmpfs`/`-v` → 健康检查 → 其他参数 → 镜像 → 命令 → 参数

### Requirement: 留空就不下发
除"后台运行"默认勾着之外,哪个字段留空就不写它那个选项;加了一行却没填,整行视同不存在,
不会留下空的 `-p`/`-v`/`-e`(依据见 `docs/notes/run-command.md`)。

#### Scenario: RB-006 留空的值字段不产出选项
- **WHEN** 只填镜像,容器名称、主机名、网络、CPU 数、内存上限、工作目录、用户全部留空
- **THEN** 命令就是 `wslc run -d <镜像>`,读不到 `--name`、`-h`、`--cpus`、`-m`、`-w`、`-u` 中的任何一个

#### Scenario: RB-007 整行留空视同这一行不存在
- **WHEN** 点「添加端口」「添加挂载」「添加环境变量」各一次,新行一个字都不填,镜像已填
- **THEN** 命令里没有空的 `-p`、`-v`、`-e` 片段
- **AND** 顶上不为这些空行报任何问题

### Requirement: 还差什么就一次列全,复制和执行都不放行
校验先于动作:顶上「还差这些就能执行:」一次列出全部问题,复制与就地执行共用同一套
有效性判断(依据见 `docs/notes/run-command.md`)。

#### Scenario: RB-008 镜像为空时复制键直接灰掉
- **WHEN** 把镜像清空
- **THEN** 顶上读得到「还差这些就能执行:」和「镜像不能为空 —— 至少要指定一个镜像。」
- **AND** 「复制」直接灰掉点不动,「就地执行」同样不放行

#### Scenario: RB-009 多个问题一次列全,各带行号
- **WHEN** 第 1 行端口没填容器端口,同时第 2 行环境变量的变量名里带了 = 号
- **THEN** 顶上一次读到「端口第 1 行:容器端口不能为空。」和「环境变量第 2 行:变量名不能为空,也不能带 = 号。」
- **AND** 不是只报第一条就没了下文

#### Scenario: RB-010 问题修完,放行跟着回来
- **WHEN** 照着清单逐条修好
- **THEN** 「还差这些就能执行:」整块消失
- **AND** 「复制」和「就地执行」恢复可点

### Requirement: 每条提示都说清是哪一行,必要时回显原值
能当场判定的错都拦在客户端:提示带行号定位到具体哪一格,用户填的怪值原样回显,不用猜是谁惹的。

#### Scenario: RB-011 不像端口的值,原样回显在提示里
- **WHEN** 第 1 行端口的容器端口填 `abc`(或 0、70000、90-80)
- **THEN** 读到「端口第 1 行:abc 不像端口(可用 8080 或 8000-8010)。」
- **AND** 提示里回显的就是用户填的那个原值

#### Scenario: RB-012 范围只有两端等长才放行
- **WHEN** 一行端口主机端口填 `8000-8010`、容器端口填 `80`
- **THEN** 读到「端口第 1 行:两端要么都写单个端口,要么都写同样长度的范围。」
- **AND** 容器端口改成 `80-90` 后这条消失,命令里有 `-p 8000-8010:80-90`

#### Scenario: RB-013 协议只认 tcp 或 udp
- **WHEN** 一行端口的协议取值既不是 tcp 也不是 udp
- **THEN** 读到「端口第 1 行:协议只能是 tcp 或 udp。」

#### Scenario: RB-014 挂载行缺来源
- **WHEN** 第 1 行挂载只填了容器路径
- **THEN** 读到「挂载第 1 行:缺少来源(主机路径或卷名)。」

#### Scenario: RB-015 挂载的容器内路径必须以 / 开头
- **WHEN** 第 1 行挂载填了来源,容器路径写 `app/data`
- **THEN** 读到「挂载第 1 行:容器内路径必须以 / 开头。」

#### Scenario: RB-016 tmpfs 路径同理
- **WHEN** 第 1 行 tmpfs 写 `tmp`
- **THEN** 读到「tmpfs 第 1 行:路径必须以 / 开头。」

#### Scenario: RB-017 变量名与标签键不能空也不能带 = 号
- **WHEN** 第 1 行环境变量变量名留空,第 2 行标签的键里带 = 号
- **THEN** 读到「环境变量第 1 行:变量名不能为空,也不能带 = 号。」
- **AND** 读到「标签第 2 行:键名不能为空,也不能带 = 号。」

#### Scenario: RB-018 健康检查的重试次数要整数
- **WHEN** 「重试次数」填 `3.5`
- **THEN** 读到「健康检查的重试次数需要是整数。」

#### Scenario: RB-019 CPU 数要数字
- **WHEN** 「CPU 数 (--cpus)」填 `abc`、`0` 或负数
- **THEN** 读到「CPU 数需要是数字,例如 0.5、1、2.5。」
- **AND** 「健康检查的重试次数」填 `3.5`、`0` 或负数时同理,要的是整数

### Requirement: 不离开这一屏直接把容器跑起来
「就地执行」把表单里那条命令交给 `wslc`:默认后台秒回容器 ID,取消勾选则前台逐行出话;
运行中可终止,`wslc` 说什么界面就呈现什么(依据见 `docs/notes/run-command.md`)。

#### Scenario: RB-020 后台执行拿到容器 ID
- **WHEN** 填好镜像、保持「后台运行」勾着,点「就地执行」
- **THEN** 「执行输出」框拿到 `wslc run -d` 写出的那一行 64 位容器 ID
- **AND** 界面读得到"已运行容器 <这个 ID>,可到「容器」页查看。"

#### Scenario: RB-021 取消勾选后台,容器输出逐行实时落框
- **WHEN** 取消「后台运行 (-d)」后就地执行,容器一边跑一边有输出
- **THEN** 这些输出逐行进「执行输出」框,不等容器退出才出现

#### Scenario: RB-022 执行期间不放行第二次触发
- **WHEN** 有一次就地执行正在进行
- **THEN** 界面读得到「正在执行…」
- **AND** 此时再点「就地执行」不会起第二条 `wslc`

#### Scenario: RB-023 终止说的是杀了谁
- **WHEN** 执行进行中点终止
- **THEN** 读到「已终止 wslc 进程;前台跑的容器可能已随之退出,请到容器页确认。」
- **AND** 已经写进「执行输出」框的内容仍看得见

#### Scenario: RB-024 失败时把 wslc 的报错原样呈现
- **WHEN** 就地执行以非 0 退出,`wslc` 在 stderr 写了错误描述和一句样板话
- **THEN** 界面读到那句错误描述,不是光秃秃一句"失败"
- **AND** 读不到"如果此错误是意外错误,请考虑搜索现有问题或…"这句样板话

### Requirement: 「复制」真的复制得上
剪贴板是延迟交付的,别的进程随时可能正开着它;重试并回读确认,别把已经成功的复制报成失败
(依据见 `docs/dev-notes.md` 第 38 条)。

#### Scenario: RB-025 剪贴板里就是界面上那条
- **WHEN** 表单有效时点「复制」
- **THEN** 剪贴板内容与界面上那条命令逐字相同
- **AND** 读到「命令已复制到剪贴板。」

#### Scenario: RB-026 剪贴板被占用不误报失败
- **WHEN** 复制那一刻另一个进程正开着剪贴板
- **THEN** 界面重试并回读确认,最终仍报「命令已复制到剪贴板。」
- **AND** 拿去终端粘得出完整命令

#### Scenario: RB-027 确认真没复制上才报失败
- **WHEN** 重试并回读后剪贴板里确实没有这条命令
- **THEN** 读到「复制到剪贴板失败,请手动选中命令文本。」

### Requirement: 把剪贴板里的命令读回来接着改
「粘贴并编辑」认本应用生成的、也认终端里手写的 `wslc run`;认得的选项各归各的控件,
认不出的整段进「其他参数」,读不懂的一律不动表单(依据见 `docs/notes/run-command.md`)。

#### Scenario: RB-028 四种写法都认
- **WHEN** 剪贴板里依次是 `wslc run …`、`wslc.exe run …`、绝对路径开头的 `wslc.exe run …`、`wslc container run …`
- **THEN** 四种都读得回来,表单按各自的值填好
- **AND** 每次都读到「已从剪贴板读回命令,可以继续在表单里改。」

#### Scenario: RB-029 不是 wslc run 的一律拒绝,且不动表单
- **WHEN** 剪贴板里是 `docker run …`、光一颗 `wslc`、或 `wslc ps`
- **THEN** 各读到「这不是 wslc run 命令,没法读回来。」
- **AND** 已经填好的表单一个字都不变

#### Scenario: RB-030 剪贴板没文本另说一句
- **WHEN** 剪贴板里没有文本时点「粘贴并编辑」
- **THEN** 读到「剪贴板里没有文本,先复制一条 wslc run 命令再来。」
- **AND** 表单同样不动

#### Scenario: RB-031 读回来的字段各归各位,命令立刻跟着变
- **WHEN** 读回一条带 `--rm`、`--pull always`、`-e`、`-p`(含绑定 IP)、`-v` 和命令与参数的完整命令
- **THEN** 对应勾选项与每一格的值和命令里写的对上,端口行连绑定 IP 都摆回原格
- **AND** 右边那条命令当场跟着重拼,不再挂着旧表单的值

#### Scenario: RB-032 认不出的选项连取值整段进「其他参数」
- **WHEN** 读回一条带 `--gpus all`、`--dns 8.8.8.8`、`--ulimit` 或非标准 `--pull` 取值的命令
- **THEN** 这些选项连同取值原样出现在「其他参数(原样追加)」那一格
- **AND** 一个都不会错落到别的控件里

#### Scenario: RB-033 盘符带冒号与带空格的值都读得回来
- **WHEN** 读回一条挂载写着 `C:\data:/app:ro`、某个值用引号包着空格的命令
- **THEN** 挂载行的来源读得到 `C:\data`、容器路径读得到 `/app`、「只读」是勾着的
- **AND** 带空格那个值没被空格切成两截

#### Scenario: RB-034 显示→读回→再显示,结果不变
- **WHEN** 把界面上那条复制出去、原样「粘贴并编辑」读回来,再看右边
- **THEN** 重新生成的命令与原来那条逐字相同

### Requirement: 拉取策略这一格不替 wslc 写死默认
`--pull` 的真实默认是 missing;界面上的"默认"= 不下发这个选项,让 wslc 自己的默认生效
(依据见 `docs/notes/run-command.md`)。

#### Scenario: RB-035 不选时显示"默认(缺了才拉)"且命令不带 --pull
- **WHEN** 拉取策略这一格从没动过
- **THEN** 框里显示「默认(缺了才拉)」
- **AND** 命令里读不到 `--pull`

#### Scenario: RB-036 选 never 命令就长出 --pull never
- **WHEN** 把拉取策略选成 never
- **THEN** 命令里出现 `--pull never`

#### Scenario: RB-037 读回带 --pull missing 的命令,那一格跟着变
- **WHEN** 读回一条带 `--pull missing` 的命令
- **THEN** 拉取策略框里同步显示 missing
- **AND** 命令仍带着 `--pull missing`

### Requirement: 镜像候选只是搭手,不是拦路
候选只是帮把手:取不到就空着,手打永远不受影响;一律用完整引用、不猜短名
(道理写在 `docs/notes/run-command.md`)。

#### Scenario: RB-038 候选用 wslc images 的完整引用
- **WHEN** 本机 wslc 可用且有镜像时进入本页
- **THEN** 镜像格子的候选列表读得到 `wslc images` 里那些带仓库前缀的完整引用

#### Scenario: RB-039 取不到候选就留空,手打不受影响
- **WHEN** 本机没有 wslc 或镜像列表读失败
- **THEN** 候选是空的,不弹错
- **AND** 直接手打一个镜像引用照样把命令长出来

### Requirement: 一键清空回到初始状态
「清空」把整张表单一次性回到初始(后台运行仍勾着),行集合、输出、提示一并抹平;
执行进行中不放行。

#### Scenario: RB-040 清空后回到第一条命令
- **WHEN** 一张填了各种行和值、也执行过的表单上点「清空」
- **THEN** 所有字段回到初始,「后台运行」仍勾着,加过的行没了
- **AND** 「执行输出」与错误/成功提示一并清空,命令回到 `wslc run -d`

#### Scenario: RB-041 执行进行中不放行清空
- **WHEN** 就地执行正进行中点「清空」
- **THEN** 这颗键点不动,表单与输出原样不动

### Requirement: 按下「就地执行」就记下那条命令
历史记的是"这条没跑对,我要接着改"的工作现场:按下执行即记、不问成败,最新在前,
只活一个会话、不落盘(依据见 `docs/notes/run-command.md`)。

#### Scenario: RB-042 跑失败的那条也在历史里
- **WHEN** 点「就地执行」,这一次跑失败了
- **THEN** 「执行历史」最前一条仍是当时那条命令
- **AND** 该行显示执行时刻与命令原文

#### Scenario: RB-043 最新在前,连续同一条只记一次
- **WHEN** 先后执行两条不同命令,随后又原样重复执行了最新那条
- **THEN** 历史按最新在前排
- **AND** 连续相同的那两条只占一行

#### Scenario: RB-044 超出 100 条挤掉最旧的
- **WHEN** 会话里执行的命令超过 100 条不同写法
- **THEN** 历史里只有最近 100 条,最旧的那条不再出现

#### Scenario: RB-045 点恢复走与剪贴板读回同一条路
- **WHEN** 点历史某行右侧的恢复入口(tooltip 写着「把这条命令填回表单,继续编辑」)
- **THEN** 表单按那条命令填好,右边命令跟着变
- **AND** 读到「已从执行历史读回命令,可以继续在表单里改。」
- **AND** 填回结果与把同一条命令贴进剪贴板再「粘贴并编辑」完全一样

#### Scenario: RB-046 执行中点恢复只给提示不改表单
- **WHEN** 就地执行正进行中点某行的恢复
- **THEN** 读到「正在执行,先取消或等它跑完再恢复历史。」
- **AND** 表单与右边命令都不变

#### Scenario: RB-047 没执行过时历史说的是空话
- **WHEN** 本次启动以来还没就地执行过任何命令
- **THEN** 「执行历史」读得到「还没有就地执行过命令。执行过的命令按最新在前留在这里,最多 100 条。」

#### Scenario: RB-048 重开应用历史就没了
- **WHEN** 执行过几条后关掉应用再打开
- **THEN** 「执行历史」回到空态,历史从不写进任何文件

### Requirement: 这一页只管 wslc run
compose、多容器编排、`wslc build` 不在这一屏;长尾选项只走"其他参数"一格;
输出框只保证看得见;终止只杀本应用起的进程(依据见 `docs/notes/run-command.md`)。

#### Scenario: RB-049 界面上找不到 run 以外的入口
- **WHEN** 把这一页从头翻到尾
- **THEN** 见到的字段与行全都是拼一条 `wslc run` 的
- **AND** 没有 compose、多容器或 `wslc build` 的任何入口

#### Scenario: RB-050 长尾选项原样透传、不校验
- **WHEN** 在「其他参数(原样追加)」里写 `--mount`、`--ip`、`--cidfile` 这类选项,取值写成什么样都算
- **THEN** 界面不对它们报任何问题
- **AND** 命令把原话照抄在自己该在的那一段

#### Scenario: RB-051 输出框是纯文本,只管看得见
- **WHEN** 执行产生了输出;以及执行之前看同一个框
