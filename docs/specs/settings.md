# settings

## Purpose
设置这一块:选中即生效即存盘的约定、`settings.json` 读不回来时怎么兜底、关于卡片给全那些
"出问题时要报给人"的信息。主题与语言的界面表现在 `theme.md` / `i18n.md`,
镜像加速卡片里的改写规则在 `registry-mirror.md`。存盘与容错的由来见 `docs/notes/settings-storage.md`。

### Requirement: 选中即生效,没有"保存"这一步
#### Scenario: SET-001 设置页给得出这几块
- **WHEN** 从导航底部或顶栏齿轮进入设置页
- **THEN** 读得到副标题"界面外观、语言与运行环境",往下依次是「外观」(主题、语言两组)、「镜像加速」卡片、「关于」
- **AND** 每组里当前生效的那一项处于选中态

#### Scenario: SET-002 界面上找不到"保存"那颗键
- **WHEN** 在设置页改任意一项(主题、语言、镜像地址、勾选项)
- **THEN** 整页读不到"保存 / 应用 / 确定"这类按钮
- **AND** 改完立刻生效,不需要再点任何键

#### Scenario: SET-003 回填选中态不算一次修改
- **WHEN** 只是进设置页看一眼、一项都没动,再离开
- **THEN** 设置文件的内容不因这次进入而被改写(回填选中态不触发一次存盘)

### Requirement: 读不回来的设置不许把界面搞崩
设置文件在 `%LOCALAPPDATA%\wsld\settings.json`,用户手得着它:记事本存出来带 BOM、
手写 JSON、写坏、只读目录都可能发生。任何一档都只回落到默认值。

#### Scenario: SET-004 文件还不存在时照常启动
- **WHEN** 第一次启动(设置文件还没被写过)
- **THEN** 应用正常打开,主题与语言都落在「跟随系统」
- **AND** 设置页读不到任何错误提示

#### Scenario: SET-005 文件内容坏掉时回默认值
- **WHEN** 设置文件被改成非法 JSON(半个括号、截断都行)后再启动
- **THEN** 应用照常打开,各项用默认值(跟随系统 / 跟随系统)
- **AND** 不弹错误框、不崩,界面不说"设置文件坏了"这种话

#### Scenario: SET-006 记事本手改过的文件要读得动
- **WHEN** 用记事本或 Visual Studio 把设置文件存成带 BOM 的 UTF-8、或加了注释、或留了尾逗号、或把属性名改成不同大小写,然后重启应用
- **THEN** 用户选过的那些档位在重启后仍在
- **AND** 不出现"我明明选了深色,重启又变回跟随系统"这种被莫名其妙重置的现象

#### Scenario: SET-007 存不进去只是没存住
- **WHEN** 设置文件所在目录不可写(或文件被占用)而保存失败
- **THEN** 当前界面照常工作、刚选的那一档当场生效
- **AND** 界面不崩,也不弹"保存失败"这类打断操作的框

#### Scenario: SET-008 认不出的字段一律忽略
- **WHEN** 设置文件里写着当前版本不认识的新字段
- **THEN** 认识的那些字段照常读回,不认识的被丢掉
- **AND** 启动与存盘都不受影响

### Requirement: 关于卡片把要报给人的信息给全
版本、`wslc.exe` 落在哪、设置文件在哪儿 —— 只有这一处落脚点,不散落到别的页面上。

#### Scenario: SET-009 关于卡片读得到应用版本
- **WHEN** 看设置页的「关于」
- **THEN** 「应用版本」后面读得到一个版本号
- **AND** 它与程序自身声明的版本一致,且不带提交号尾巴(界面上不会出现 `+4527683` 这种串)

#### Scenario: SET-010 关于卡片读得到 wslc 的路径
- **WHEN** 本机装有 wslc
- **THEN** 「wslc 路径」后面读得到应用实际用的那份 `wslc.exe` 的完整路径
- **AND** 这个路径与容器页/镜像页数据来自哪份 CLI 是同一份(定位优先级的契约见 `container-list.md`)

#### Scenario: SET-011 没装 wslc 时说得清楚
- **WHEN** 本机找不到 `wslc.exe`
- **THEN** 「wslc 路径」那一行读得到"未找到 wslc.exe",不是空白也不是半截路径

#### Scenario: SET-012 关于卡片读得到设置文件的位置
- **WHEN** 看「设置文件」那一行
- **THEN** 读得到设置文件的完整路径,而且按这个路径真能找到这个文件

### Requirement: 存下来的字段要能读懂、要留默认档
新增设置项必须给默认值,老配置文件才读得动;数字编号不进配置文件。
纪律的由来见 `docs/notes/settings-storage.md`。

#### Scenario: SET-013 配置字段用能读懂的名字
- **WHEN** 改过主题或语言后打开设置文件
- **THEN** 那两项存的是能读懂的名字(如 `Dark`、`En`),不是数字编号

#### Scenario: SET-014 老配置文件在新版本里读得动
- **WHEN** 拿一份只有主题与语言两项的老设置文件启动本版应用
- **THEN** 这两项照常生效,镜像加速那两项走默认档:不使用镜像源、拉取后改名开着
- **AND** 界面里不出现任何"字段缺失"的痕迹

#### Scenario: SET-015 配置里写 null 的镜像地址当空处理
- **WHEN** 设置文件里镜像地址那一项被写成 `null`
- **THEN** 行为等同"留空 = 不使用镜像源",应用照常启动、不崩
- **AND** 下一次存盘时那一字段写的是空串,不再写回 `null`

#### Scenario: SET-016 存的是用户原样写的那串地址
- **WHEN** 在镜像加速卡片里填 `https://Docker.1ms.run/`(带协议、带大写、带结尾斜杠)后离开这一页
- **THEN** 设置文件里存的就是这串原样输入(只去掉首尾空白)
- **AND** 回到这一页看到的还是自己写的那串,不是被应用改写后的规范化结果(规范化是用的时候现算,见 `registry-mirror.md`)

#### Scenario: SET-017 第一次存盘就把该建的目录建出来
- **WHEN** `%LOCALAPPDATA%\wsld` 这个目录还不存在,而用户改了一项设置
- **THEN** 设置文件照常写出来,界面不报错、不需要用户先自己建目录

#### Scenario: SET-018 勾选项也活到下次启动
- **WHEN** 把"拉取后把镜像改名回我输入的名字"从勾着改成不勾,关掉应用再打开
- **THEN** 这一项仍是不勾的状态,改写仍然发生但拉完不改名(行为见 `registry-mirror.md` 的 RM-018)
