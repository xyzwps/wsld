# pull-progress

## Purpose
点下拉取之后、出结果之前的那块实时进度: wslc 在终端里画的那张分层屏幕原样搬上屏,
旁边跟一句"已下载多少 · 完成几层"。命令与结果的措辞归 `image-actions.md`(IA),
拉之前引用怎么被镜像源改写归 `registry-mirror.md`(RM)。

### Requirement: 拉取只跑一遍,进度不是靠重跑换来的
界面拿到的实时分层来自同一条 `wslc pull <引用>` —— 不加 `-q`,也不为了看进度再跑第二遍
(依据见 `docs/notes/conpty-pull-progress.md`)。拿不到实时屏幕时宁可没有,也不改结果。

#### Scenario: PP-001 命令映射没被进度改动
- **WHEN** 从「镜像」页发起一次拉取
- **THEN** `wslc` 那侧只收到 `pull <引用>` 这一条,参数里没有 `-q`
- **AND** 整个拉取过程这一条命令只跑一遍,进度是靠读它的输出读出来的

#### Scenario: PP-002 实时屏幕拿不到就退回原样
- **WHEN** 本机的伪终端起不来(被拦住或系统太旧), wslc 认为自己不在终端里
- **THEN** 拉取进行到一半时看得见只有转圈与 "正在拉取 X · 已等待 N 秒",分层进度一行都没有
- **AND** 结束后的提示与列表跟走实时进度时一模一样,界面不弹错误框,也不解释为什么没进度

### Requirement: 一张屏幕原样搬上来
wslc 用"原地回写"画分层进度: 每个分层固定占一行,新状态盖在同一行上,不是无限追加
(依据见 `docs/notes/conpty-pull-progress.md`)。界面跟着这个形状,一行只报一个分层的最新状态。

#### Scenario: PP-003 一行一个分层,行数只随层数长
- **WHEN** 一次拉取里 wslc 把同一个分层的状态刷了十几回
- **THEN** 进度区里那个分层始终只占一行,写的是它最新的状态
- **AND** 整块的行数等于本机这一趟见过的分层数,不随刷新次数变长

#### Scenario: PP-004 头行与收尾三行不进这一列
- **WHEN** 屏幕上同时有 `24.04: Pulling from library/ubuntu` 这类头行,以及末尾的 `Digest:` / `Status:` / 完整引用三行
- **THEN** 它们不占分层的那几行位置
- **AND** 汇总里的层数也不把它们算成一个层

#### Scenario: PP-005 那块区域只读、等宽、可整块复制
- **WHEN** 拉取进行中,用户在进度区里打字或按删除键
- **THEN** 一个字都改不动,内容是等宽字体
- **AND** 整块复制到别处时仍是一行一个分层,行没被拼到一起去

#### Scenario: PP-006 高约 160 DIP,超出后自己在框里滚
- **WHEN** 分层多到这一块的行数超出它的高度
- **THEN** 这一块的最高处约 160 DIP,不把它下面那几排镜像行顶出屏幕
- **AND** 视图停在最新写入的那一行上,框内出滚动条而不是页面无限变长

### Requirement: 旁边那句话说的是"下了多少、完成几层"
汇总由分层行算出来: 每层的字节取它这一趟里报过的最大值,完成只认终态
(真机实测坑: 某层进入 `Download complete` 之后那一行不再带字节数,见
`docs/notes/conpty-pull-progress.md` 与开发备忘第 30 条)。

#### Scenario: PP-007 汇总一句话跟着屏幕走
- **WHEN** 拉取进行到一半,已经报出若干分层与各自的字节
- **THEN** 读得到 "已下载 X · 完成 N/M 层", M 是见过的分层数

#### Scenario: PP-008 已下载只增不减
- **WHEN** 某层从 `Downloading 544.5kB` 变成 `Download complete`,那一行不再报字节
- **THEN** 这层的字节仍算在"已下载"里,那个数不会退回 0,也不会往回跳
- **AND** 同一层在一趟拉取里报过更大的数时取更大的那个

#### Scenario: PP-009 只有终态才算完成一层
- **WHEN** 屏幕上出现 `Verifying Checksum`、`Download complete`、`Extracting 5.5MB/27MB` 这些中间状态
- **THEN** 完成层数都不因此加一
- **AND** 只有 `Pull complete` 与 `Already exists` 各算一层完成

#### Scenario: PP-010 字节按 1000 进制写
- **WHEN** 分层行报出的字节累计到 544500 个
- **THEN** 汇总读得到 "已下载 544.5 kB",再往上到 1100000 个时读得到 "1.1 MB"
- **AND** 单位风格与 wslc 自己写分层进度时同一套
- **AND** 解压阶段那行写着 `Extracting 5.5MB/27MB` 时,这一层按 27 MB 这个全量计入

#### Scenario: PP-011 还没拿到分层时这一句不占位置
- **WHEN** 刚点下拉取, manifest 还没回来,屏幕上一个分层都还没有
- **THEN** 进度区与那句汇总都空着不占位置
- **AND** 看得见的只有转圈和 "正在拉取 X · 已等待 N 秒"

### Requirement: 每一趟拉取自己算自己
上一趟的分层行、字节数都不能跟着下一趟跑 —— 那会让第二趟开局就挂着别人的数字
(依据见开发备忘第 30 条)。

#### Scenario: PP-012 第二趟从 0 开始
- **WHEN** 上一趟拉取已经收尾,用户紧接着发起第二趟
- **THEN** 进度区当场是空的, "已下载"从 0 起算,不出现上一趟的数字
- **AND** 上一趟那些分层行一行都不留在屏幕上

### Requirement: 节奏是 wslc 的,应用不造进度
实测 wslc 自己约 15–20 秒才回写一帧,它也不给总字节数 —— 所以界面没有百分比,也不许凭猜测
往前推数字(依据见 `docs/notes/conpty-pull-progress.md`)。

#### Scenario: PP-013 两帧之间界面上的数字不动
- **WHEN** wslc 迟迟没有回写新的一帧
- **THEN** 分层行与"已下载 / 完成 N/M 层"都停在上一帧的内容,一秒一秒地自己往前蹭
- **AND** 界面从头到尾没有百分比,也没有"预计剩余时间"这类猜出来的东西

#### Scenario: PP-014 等待多久仍然看得见
- **WHEN** 一个分层几十秒停在 `Pulling fs layer`、"已下载 0 B"
- **THEN** "正在拉取 X · 已等待 N 秒"里的 N 一秒一步地涨
- **AND** 用户看得见卡在哪一层、已经等了多久,不用靠猜判断它死没死

### Requirement: 收场时进度与汇总一起退场
实时进度只属于"正在进行"这件事,无论成功、失败还是取消,留下来的应该是结果和列表。

#### Scenario: PP-015 三种收场都收拾干净
- **WHEN** 一次拉取以成功、失败或取消收尾
- **THEN** 进度区与那句汇总一起收起,屏幕上不留半截分层行
- **AND** 剩下的是结果提示与刷新后的列表(取消的那次不刷新)

#### Scenario: PP-016 失败横幅里看得见真正的报错
- **WHEN** 拉取失败,屏幕上几十行 `Downloading …` 与末尾的报错混在一起
- **THEN** 红色错误条里是非分层进度的那些行,也就是引擎写的错与 `错误代码:` 那一行
- **AND** 用户不用自己在一堆进度文本里找那句真正失败的话
