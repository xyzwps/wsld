# container-logs

## Purpose
容器详情区「日志」页签:两种读法(查看日志 / 实时日志)各自的命令、校验、上屏节奏与会话收尾。
页签的存在与切换后的可见结果归 `container-detail.md`(CD);容器起停动作本身归 `container-actions.md`(CA)。
两种读法的分工:"读历史"和"盯新行"是两件不同的事,界面上也各走各的命令、各有一份文本。

### Requirement: 两种读法各发各的命令,不许混
一次性读法拼成 `logs [-t] [-n N] <容器>`,实时读法拼成 `logs -f [-t] --since <Unix 秒> <容器>`,
顺序固定、实时那条永远不带 `-n`;没有 `--since` 的 `-f` 实测会把全部历史先冲出来,那就不是"实时"(依据见
`docs/notes/wslc-logs.md`)。

#### Scenario: LG-001 「查看日志」拼出一条一次性命令
- **WHEN** 勾了"显示时间戳"、行数选了"最近 500 行",点「查看日志」
- **THEN** wslc 那侧收到 `logs -t -n 500 <容器>`,顺序就是这么写的
- **AND** 这条命令里读不到 `-f`,跑完这一次就结束

#### Scenario: LG-002 选"全部"时不发出 `-n`
- **WHEN** 行数下拉选到"全部",点「查看日志」
- **THEN** 收到的命令是 `logs <容器>`,一个行数控件的值都不带,历史有多少给多少

#### Scenario: LG-003 「实时日志」拼出带起点的跟随命令
- **WHEN** 勾了"显示时间戳"、点「实时日志」
- **THEN** 收到的命令是 `logs -f -t --since <点下这一刻的 Unix 秒> <容器>`
- **AND** 这条命令里读不到 `-n` —— 起点之后的行不该再被行数截断

#### Scenario: LG-004 没勾时间戳就两条命令都不带 `-t`
- **WHEN** "显示时间戳"没勾上,分别走两种读法
- **THEN** 「查看日志」发的是不带 `-t` 的读法,「实时日志」也是不带 `-t` 的跟法

#### Scenario: LG-005 没起点就没有实时
- **WHEN** 一次实时请求拿不到正的起点时刻
- **THEN** 进程一次都不起,界面上不出现"其实在倒历史"的半截实时

#### Scenario: LG-006 两种读法各守各的门
- **WHEN** 界面走到日志读取,而当前请求的模式与它要走的读法对不上
- **THEN** 这次读取直接中止,既不把"一次性读"挂成常驻进程,也不把"跟随"提前读一屏就断

#### Scenario: LG-032 强调色只表示"实时正在收"
- **WHEN** 刚进「日志」页签、刚点过「查看日志」,或者一趟实时已经结束/被停下
- **THEN** 两颗读法入口都是普通按钮的样子,没有哪颗顶着强调色(此刻屏上并没有正在进行的实时)
- **AND** 实时日志正在进行时,强调色只落在「实时日志」上

### Requirement: 发命令之前先把输入校验干净
实时必须有起点;容器标识不能为空;查看模式的行数不能越界 —— 非法输入在启动进程之前就被挡下,
免得换回 wslc 那 8 行没有价值的 usage 噪音(依据见 `docs/notes/wslc-logs.md`)。

#### Scenario: LG-007 空容器标识不起进程
- **WHEN** 触发任一种读法时手里其实没有可用的容器标识
- **THEN** wslc 那侧一条命令都没收到,连进程都不起
- **AND** 界面不崩,也不出现 wslc 那 8 行 usage 输出

#### Scenario: LG-008 行数只能从那几档里选
- **WHEN** 打开「行数」那一格
- **THEN** 只能选到固定那几档(最近 100 / 200 / 500 / 1000 / 2000 行与"全部"),界面上没有一处能敲进越界数字的输入框
- **AND** 选了哪一档,发出去的 `-n` 就是那个数;选"全部"时不带 `-n`

### Requirement: 日志文本进界面,空行留着、长行截断
输出按行拆开进只读文本区:中间空行是日志的一部分,单行过长只截显示,不截存储(依据见
`docs/notes/wslc-logs.md`)。

#### Scenario: LG-009 中间空行原样保留
- **WHEN** 读回的日志里夹着空行
- **THEN** 空行在显示区占一行,不因为"没字"被抹掉
- **AND** 只有正文末尾多余的空尾巴不被算成一行

#### Scenario: LG-010 超长行截断并留话
- **WHEN** 有一行超过了显示宽度上限
- **THEN** 这一行只贴出前一段,末尾跟着读得到"…(本行过长,已截断显示)"
- **AND** 日志区是只读的等宽文本区,可全选、可复制,打字改不动一个字

### Requirement: 勾了时间戳才动行首
只有本次请求带了 `-t`,才把行首的 UTC 时间戳换成本地时分秒;其余情况一个字都不改行内容。

#### Scenario: LG-011 时间戳换成本地时分秒
- **WHEN** 勾了"显示时间戳",wslc 回的行首是一串 UTC 时间戳
- **THEN** 行首被换成本地 `HH:mm:ss.fff` 那种写法,行里剩下的内容原样跟在后面

#### Scenario: LG-012 解析不了就原样站着
- **WHEN** 开了时间戳,而某一行行首不是能认出的时间戳格式
- **THEN** 这一行原样显示,不被改写、也不被吞掉

### Requirement: 错误进提示位,不进日志文本区
读取失败(非 0 退出码)时,清洗后的一句话写进日志区下方的提示,日志文本区不被污染;
清洗规矩与 CL-018、CL-019 是同一套,不在这里重复。

#### Scenario: LG-013 读失败给的是人话,不是半截日志
- **WHEN** 一次读取以非 0 退出码失败(stderr 有错误描述与 `错误代码:` 一行)
- **THEN** 提示位置读得到清洗后的一句话,读不到"欢迎提 issue"那句样板话
- **AND** 日志文本区保持失败前的样子,错误文本没被当成日志行贴进去

### Requirement: 实时逐行到屏,慢日志也不装死
实时读到一行就往外递、绝不攒到进程结束;上屏走攒批 + 定频催屏,两头都要守住。攒批避免每行重绘,
催屏保证"每秒一行"的慢日志也看得见在动(依据见 `docs/notes/wslc-logs.md` 与 `docs/dev-notes.md` 第 19、20 条)。

#### Scenario: LG-014 实时是一条一条长出来的
- **WHEN** 盯着正在持续输出的容器跑「实时日志」
- **THEN** 新行一条一条出现在文本区,不是等容器停下才一次贴出全部

#### Scenario: LG-015 慢日志也看得见在动
- **WHEN** 实时日志很久只来一两条(比如每秒一行的容器)
- **THEN** 状态栏"共 N 行 · 最近加载 时:分:秒"跟着新行一秒一秒往后走,不像卡死
- **AND** 高频日志按批成块长出,不卡成一整块空白

### Requirement: 只显示最近 2000 行,丢掉的要说
实时挂着跑一夜不至于吃满内存;丢掉的行数在状态栏说得出口(依据见 `docs/notes/wslc-logs.md`)。

#### Scenario: LG-016 超过两千行就丢最早的
- **WHEN** 界面已显示的行突破 2000 行上限
- **THEN** 屏幕上始终留着最近 2000 行,最早的那批被请出去
- **AND** 状态栏跟着读出"已丢弃最早的 N 行",N 是累计丢掉的行数

### Requirement: 空日志是正常,不是错误
实测已退出或从未启动的容器,`logs` 返回退出码 0 + 空输出;界面把它说成"没内容",不谎报成失败
(依据见 `docs/notes/wslc-logs.md`)。

#### Scenario: LG-017 空输出读得到那句"没有输出"
- **WHEN** 读取一个已停止(或从未启动)的容器,读回 0 行
- **THEN** 提示位置读得到"这个容器目前没有任何输出。"
- **AND** 不出现错误条,退出码 0 就是它真的没话

### Requirement: 同一时刻只挂一个日志进程
两种读法共用一把闩:读的过程中点任何日志入口都被吞掉,两个进程抢不到同一个容器(依据见
`docs/notes/wslc-logs.md`)。

#### Scenario: LG-018 读进行中,日志入口全体僵住
- **WHEN** 一次日志读取(查看或实时)正在进行
- **THEN** 「查看日志」「实时日志」入口都不响应第二次点击,不会另起第二个 `wslc logs` 进程抢同一个容器
- **AND** 行数下拉与"显示时间戳"开关同时锁死,进度圈出现

### Requirement: 只有运行中的容器可以实时
对已停止的容器点「实时日志」要灰掉,并在悬停说明里说清为什么;要翻旧日志用「查看日志」(依据见
`docs/notes/wslc-logs.md`)。

#### Scenario: LG-019 停止的容器开不了实时
- **WHEN** 选中一个已停止的容器,停在「日志」页签
- **THEN** 「实时日志」按钮是灰的,悬停读得到"容器没在运行,看不了实时日志;要翻旧日志请用「查看日志」。"
- **AND** 「查看日志」不受这条限制,已停止的容器照样翻旧账

#### Scenario: LG-020 运行状态一变,能不能实时跟着变
- **WHEN** 一次操作或外部变化把当前容器从运行中变成已停止(或反过来)
- **THEN** 「实时日志」的可用状态与悬停话跟着当前运行状态改口

### Requirement: 新一轮实时从空白开始,停止保留已显示的行
"从现在起"不该混进上一趟的历史;停下时眼睛看到的都留着(依据见 `docs/notes/wslc-logs.md`)。

#### Scenario: LG-021 开实时之前先把屏幕擦净
- **WHEN** 刚用「查看日志」读回一批历史,再点「实时日志」
- **THEN** 文本区先清成空白,上一趟读到的历史一行都不残留
- **AND** 屏幕从点下去这一刻的新行开始长

#### Scenario: LG-022 点「停止实时」只停不收摊
- **WHEN** 实时日志正在进行,点了「停止实时」
- **THEN** 文本区已显示的行全数保留,滚动位置不动
- **AND** 提示位置读得到"已停止实时日志。"
- **AND** 停下之后本机不再挂着这个容器的 `wslc` 进程(进程树一起收,不留半死的)

#### Scenario: LG-031 界面先看见容器被停掉,实时就地收尾
- **WHEN** 实时日志正在进行,这一页读到那个容器已经不在了(被停止或被删除)
- **THEN** 这一趟实时就地结束,提示位置读得到"已停止实时日志。"
- **AND** 「实时日志」跟着变回不可用,悬停说明改口(见 LG-019)

### Requirement: 实时结束要分四种情况说话
容器被停止时 wslc 自己安静退场、不留一句"容器已结束",这句话界面得替它说(依据见
`docs/notes/wslc-logs.md`)。

#### Scenario: LG-023 实时自然结束 → 说清多半是容器停了
- **WHEN** 用户没点「停止实时」,这一趟跟随却走到了尽头(wslc 那侧自己收场),且期间收到过新行
- **THEN** 提示位置读得到"实时日志已结束(容器多半已停止)。"
- **AND** 已上屏的行留在文本区

#### Scenario: LG-024 全程一行都没来
- **WHEN** 一次实时走到结束而期间一条新行都没收到
- **THEN** 提示位置读得到"实时日志已结束,期间没有新日志。"

#### Scenario: LG-025 实时里读出失败
- **WHEN** 一次实时因 wslc 非 0 退出的故障结束
- **THEN** 提示位置换回清洗后的错误文案(同一套规矩见 CL-018、CL-019),而不是那句"容器多半已停止"

### Requirement: 换容器、切页签、容器没了,日志会话都收尾
日志缓冲属于"这一个容器这一次会话";串台比少看更糟(依据见 `docs/notes/wslc-logs.md` 与
`docs/dev-notes.md` 第 34 条)。

#### Scenario: LG-026 换容器 = 旧会话立刻收摊
- **WHEN** 旧容器正在跑实时,列表里点了另一个容器
- **THEN** 旧容器的实时被停掉,它的行、状态与丢弃计数一并清空,新容器的日志区是空白
- **AND** 「实时日志」能不能按,按新容器的运行状态重新决定

#### Scenario: LG-027 切回「详情」只停实时不清屏
- **WHEN** 实时进行中(或已经停掉),页签切到「详情」
- **THEN** 正在跑的实时停下来,但已显示的行留着,再切回「日志」页签还都在原位
- **AND** 切页签不重开日志进程

#### Scenario: LG-028 容器被删除时,日志会话跟着收摊
- **WHEN** 当前正在看日志的容器被删除
- **THEN** 日志会话随容器一起清空,「实时日志」按钮按不可用状态处理(见 LG-019)
- **AND** 应用不崩,右栏回到"点击左侧的容器查看详情"(见 CD-001)

### Requirement: 自动滚到底默认开着,关掉不挡新行
新来的行要不要拉着视图往下跑,由用户说了算;关掉不等于不收(依据见 `docs/notes/wslc-logs.md`)。

#### Scenario: LG-029 默认自动滚到底
- **WHEN** 进入「日志」页签,什么都没勾过
- **THEN** "自动滚到底"处于勾选状态,新行到达时视图自己跟到底部

#### Scenario: LG-030 关掉自动滚,新行仍进缓冲
- **WHEN** 取消勾选"自动滚到底",实时继续跑
- **THEN** 新行照样落进文本区、状态栏照样推进,视图不再自动拉到底
- **AND** 用户能停在任意一处读完再自己往下走
