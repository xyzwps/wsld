# image-actions

## Purpose
镜像页上的两个动作:拉取(`wslc pull`)与删除(`wslc rmi` / `rmi -f`)—— 命令怎么发、
提示怎么说、取消与互斥怎么算、被占用时怎么升到"强制删除"。
这一列镜像本身的呈现在 `images.md`(IM),拉取途中的分层进度在 `pull-progress.md`(PP),
镜像源改写与拉后改名在 `registry-mirror.md`(RM)。

### Requirement: 一个动作只发那一条命令
命令行与 `wslc` 的实际形态对齐(依据见 `docs/notes/wslc-cli.md`): 引用先去掉首尾空白再拼进去,
删除一次只交一个引用 —— 实测 `wslc rmi A B C` 遇到第一个失败就停手,剩下的根本不被处理。

#### Scenario: IA-001 三条命令各就各位
- **WHEN** 在拉取框里写一个引用点拉取,再在某一行上确认删除(含强制那一档)
- **THEN** `wslc` 那侧依次只收到 `pull <引用>`、`rmi <引用>`、升级后的 `rmi -f <引用>`
- **AND** 引用前后多打的空格不会被带进命令里

#### Scenario: IA-002 一次只删一个引用
- **WHEN** 一个镜像有两个标签,用户删掉其中一行
- **THEN** 只发出一条 `wslc rmi <那一行的引用>`,不是把两个标签一起交上去
- **AND** 另一行照旧留在列表里

#### Scenario: IA-003 框里是空的就什么都不发
- **WHEN** 拉取框空着或只有空格,用户点拉取(删除侧拿到一个空引用时同理)
- **THEN** 读得到 "请先输入要拉取的镜像引用,例如 docker.1ms.run/library/redis:7。"
- **AND** `wslc` 那侧一条命令都没收到,拉取那颗键也点不动

#### Scenario: IA-004 回车等同于点拉取
- **WHEN** 在拉取框里写完引用按回车
- **THEN** 与点拉取那颗键一模一样: 发出 `wslc pull <引用>`,顶部转圈与提示区同步开始

### Requirement: 拉回来的结果分得清
`wslc pull` 的详细输出末尾挂着 `Status:` 一行,它能区分"真下载了新东西"和"本机本来就最新",
值得给用户两句不同的话(依据见 `docs/notes/wslc-cli.md`)。

#### Scenario: IA-005 新下载的报"已拉取"
- **WHEN** `wslc pull` 以 0 退出,输出里写着 `Status: Downloaded newer image for X`
- **THEN** 绿色提示读得到 "已拉取 X"
- **AND** 列表随后自己刷新一次,新镜像那一行出现在列表里

#### Scenario: IA-006 本来就最新的报"已是最新"
- **WHEN** 拉的是本机已有的镜像,输出里写着 `Status: Image is up to date for X`
- **THEN** 绿色提示读得到 "X 已是最新",不说"已拉取"
- **AND** 列表同样只刷新一次

#### Scenario: IA-007 没有 Status 行也照样收尾
- **WHEN** `wslc pull` 成功退出,但输出里一行 `Status:` 都没有
- **THEN** 绿色提示按 "已拉取 X" 说
- **AND** 界面不说解析失败,也不挂错误条

### Requirement: 同一时刻只有一个动作在跑
拉取与删除共用一把锁,中途列表被换掉会让用户点在被冲掉的行上,所以操作期间一律不刷新。

#### Scenario: IA-008 期间别的动作点不动
- **WHEN** 有一次拉取或删除正在进行
- **THEN** 顶部拉取键与每一行的删除键都点不动
- **AND** 硬点第二下也不会让 `wslc` 那侧多出第二个进程

#### Scenario: IA-009 操作期间不读列表
- **WHEN** 有一次拉取或删除正在进行
- **THEN** 期间点刷新不会发出 `wslc images`,列表还是原来那几行

#### Scenario: IA-010 动作一结束一切照常
- **WHEN** 拉取或删除收尾(成功、失败、取消都算)
- **THEN** 拉取键与各行删除键恢复可点,刷新照常发出 `wslc images`

### Requirement: 拉错了能停,停了就是没发生
实测半途终止 `wslc pull` 不会留下半截镜像,所以取消之后不必刷新,只需要把"已取消"说清楚。

#### Scenario: IA-011 取消只做一件事
- **WHEN** 拉取正在进行,用户点那颗只在拉取期间看得见的"取消"
- **THEN** 绿色提示读得到 "已取消拉取 X",界面不挂错误条
- **AND** `wslc` 进程随之结束,列表不刷新,手敲 `wslc images` 也看不到半截镜像

### Requirement: 提示只留新的一处
一个动作接着一个动作时,屏幕上同时挂着旧结果和新结果会让人误读,所以旧话一律让位。

#### Scenario: IA-012 开始新动作就清掉旧提示
- **WHEN** 上一次的绿色提示或红色错误条还挂着,用户开始下一次拉取或删除
- **THEN** 那两处同时空出来,不再与这一轮的结果同屏

#### Scenario: IA-013 失败说的是清洗后的一句话
- **WHEN** 动作失败, `wslc` 在 stderr 里写了错误描述、`错误代码:` 与那句"欢迎提 issue"的样板话
- **THEN** 红色错误条读得到错误描述与错误代码,读不到样板话
- **AND** 绿色提示空着,列表还是上一次成功时那几行

### Requirement: 只有"被容器占用"才升级出强制删除
`-f` 是真把镜像从磁盘上拿走,留下的容器再也起不来 —— 那是破坏性动作,平时不给(依据见
`docs/notes/wslc-cli.md` 的删除实测表)。

#### Scenario: IA-014 被占用拒绝后那一行换个键
- **WHEN** 常规删除被引擎拒绝, stderr 里是 `conflict: unable to remove repository reference … (must force)` 或 `错误代码: ERROR_SHARING_VIOLATION`
- **THEN** 那一行的键从"删除"变成"强制删除",悬停说明也跟着变成 "强制删除镜像引用 (wslc rmi -f)"
- **AND** 错误条末尾追加一句 " 该镜像正被容器使用,再点一次「强制删除」才能把它从磁盘上移除。"

#### Scenario: IA-015 别的失败不给这个选项
- **WHEN** 删除失败的原因是找不到镜像(`错误代码: WSLC_E_IMAGE_NOT_FOUND`)或别的错误
- **THEN** 那一行的键仍写着"删除",错误条里也没有那句追加的话

#### Scenario: IA-016 强制删除是第二次显式动作
- **WHEN** 已经升级到"强制删除"的那一行被再次点击
- **THEN** 先弹出标题为"强制删除镜像"的确认框,里面用红字写明"该镜像正被 N 个容器引用,强制删除后这些容器将无法再次启动。"
- **AND** 只有选了"强制删除"才发出 `wslc rmi -f <引用>`,选"取消"时 `wslc` 那侧什么都没收到

#### Scenario: IA-017 删除前先问一句,没被占用的说清只取消标签
- **WHEN** 在一个没被容器引用的行上点删除
- **THEN** 确认框标题是"删除镜像",正文是"确定要删除镜像引用 X 吗?"
- **AND** 下面补一句"如果这个镜像还有其它标签,这一步只会取消当前标签。",默认停在"取消"那颗键上

#### Scenario: IA-018 被引用的镜像在确认框里就把话说完
- **WHEN** 在一个正被 N 个容器引用的行上点删除
- **THEN** 确认框里多一句"该镜像正被 N 个容器引用,这样删除会被拒绝,届时可再选择强制删除。"
- **AND** 这一句只是预告,按下去发的仍是不带 `-f` 的 `wslc rmi <引用>`

#### Scenario: IA-019 删干净了怎么说
- **WHEN** `wslc rmi`(或 `rmi -f`)以 0 退出
- **THEN** 绿色提示读得到 "已删除 X",列表刷新一次后那一行没了
- **AND** 这一行的键回到"删除"

### Requirement: 行上的状态要活过刷新
刷新会把每一行的数据整体换掉,但"正在删除""等你确认强制删除"是用户刚做出来的决定,
不能被一次刷新抹平。

#### Scenario: IA-020 手动刷新不冲掉强制那一档
- **WHEN** 某行已经变成"强制删除",用户点了刷新而它仍被容器引用
- **THEN** 刷新前后这一行的键都写着"强制删除",中间不闪回"删除"
- **AND** 不用把常规删除再失败一次才重新拿到这个选项

#### Scenario: IA-021 占用消失了就收回这个入口
- **WHEN** 某行原本是"强制删除",刷新后它不再被任何容器引用
- **THEN** 键回到"删除",界面不再提供 `-f` 这条路
- **AND** 整行从列表消失后,它的状态一并作废,同一引用再出现时是一行全新的"删除"

#### Scenario: IA-022 正在操作的那一行看得见
- **WHEN** 某一行正在被拉取或删除
- **THEN** 这一行上读得到进行中的标记(转圈),而它自己那颗键点不动
- **AND** 别的行同样点不动(全局一次只有一个动作在飞,见 IA-008)
