# container-list

## Purpose
容器页左栏那一列容器:自己刷新、能搜、出错时怎么说话。一行只负责认出"是哪个容器";
它的完整字段在 `container-detail.md`(CD),行上那几颗操作键在 `container-actions.md`(CA)。

### Requirement: 打开应用就把容器摆出来
启动即加载一次,不必用户点任何东西。行呈现的识别信息只有名称、状态、镜像三样 ——
命令、端口、网络、ID 这些一律进详情看,留在行里只会把左栏撑宽(依据见
`docs/notes/wslc-cli.md`,行宽的几何归 `shell.md`)。

#### Scenario: CL-001 启动应用自动加载一次
- **WHEN** 本机装有 wslc,启动应用并停在「容器」页
- **THEN** 不需要任何点击,列表里就把本机容器逐条摆出来
- **AND** 每条与 `wslc list -a` 看到的容器一一对应,不多不少

#### Scenario: CL-002 一行只报名称、状态、镜像
- **WHEN** 停在「容器」页看任一行
- **THEN** 读得到容器名称、状态与镜像名
- **AND** 这一行读不到命令、端口、网络、创建时间与 ID

#### Scenario: CL-003 运行中的排前面,点的颜色跟着状态
- **WHEN** 本机既有运行中的容器也有已停止的容器
- **THEN** 运行中的那几行状态点带绿色,其余带灰色
- **AND** 运行中的行排在已停止的行前面,同档内按名称排

#### Scenario: CL-004 本机一个容器都没有
- **WHEN** 本机没有任何容器,停在「容器」页
- **THEN** 读得到"没有匹配的容器",界面不出现错误条
- **AND** 汇总读得到"共 0 个容器 · 0 个运行中"

#### Scenario: CL-005 顶部汇总报全机的数
- **WHEN** 本机有 N 个容器、其中 M 个在跑
- **THEN** 顶部读得到"共 N 个容器 · M 个运行中"
- **AND** 这两个数来自全机,不跟着搜索词或"显示已停止"的开关变

#### Scenario: CL-006 最近一次刷新看得见
- **WHEN** 列表刚刷成功
- **THEN** 读得到"最近刷新"的时刻,精确到秒(`HH:mm:ss`)
- **AND** 这个界面从头到尾没刷成功过时,那一处读得到"尚未刷新"

### Requirement: 列表自己跟着本机变化
容器可能由别的终端、别的应用起停,这一页要能兜住这种外部变化。节奏固定 3 秒、不开放调节,
界面上也不写这个数(用户不需要算);工具栏只留一颗刷新键。

#### Scenario: CL-007 停在页面上就能看到外部变化
- **WHEN** 应用开着、停在「容器」页,在另一个终端里 `wslc run` 起一个容器
- **THEN** 几秒之内这一行自己出现在列表里,不用点刷新
- **AND** "最近刷新"的时刻跟着往后走

#### Scenario: CL-008 上一次还没读完不叠加下一次
- **WHEN** 一次读取还没结束,又一个刷新节奏到了
- **THEN** 这一轮直接跳过,不会同时挂着两条 `wslc list`
- **AND** 界面不闪断,行还是原来那几行

#### Scenario: CL-009 点刷新只发那一条命令
- **WHEN** 点「刷新」那颗键
- **THEN** `wslc` 那侧只收到 `list -a --format json` 这一条命令
- **AND** 界面上没有第二处"刷新节奏"的标注文字

#### Scenario: CL-010 容器操作进行中不读列表
- **WHEN** 有一次启动/停止/重启/删除正在进行
- **THEN** 期间的自动刷新与手动刷新都不发出 `wslc list`
- **AND** 操作结束后列表照旧能刷

### Requirement: 找一个容器不用翻页
搜索与过滤只在已经读回来的数据里挑,一次进程都不起。

#### Scenario: CL-011 输入即过滤
- **WHEN** 在搜索框里逐字输入某个容器的名称、镜像名或 ID 的任一片段
- **THEN** 列表立刻只剩匹配的那些行
- **AND** 匹配不区分大小写,也不要求从头开始

#### Scenario: CL-012 过滤不惊动 wslc
- **WHEN** 输入搜索词、清空搜索词,或切换"显示已停止"
- **THEN** `wslc` 那侧一条命令都没收到

#### Scenario: CL-013 "显示已停止"默认开着
- **WHEN** 刚进入「容器」页
- **THEN** 已停止的容器和运行中的一样列出来,那颗开关处于"显示已停止"这一档

#### Scenario: CL-014 关掉之后只剩在跑的
- **WHEN** 把"显示已停止"切到隐藏
- **THEN** 已停止的行整批消失,运行中的行原样留着
- **AND** 顶部汇总那两个数仍是全机的数

#### Scenario: CL-015 清空搜索词回到全部
- **WHEN** 把搜索框里的字删干净
- **THEN** 列表回到当前开关档位下的全部容器,顺序不变

### Requirement: wslc 说什么,界面说人话
`wslc` 的输出形态不止一种(单行对象 / 每行一个对象 / JSON 数组 / 带缩进),错误一律写在
stderr 且末尾挂着那句"欢迎提 issue"的样板话。界面要读得进每一种形态,也要把套话滤掉。
依据见 `docs/notes/wslc-cli.md`。

#### Scenario: CL-016 排版怎么变都读出同样的行
- **WHEN** 同一批容器,wslc 把它们排成单行对象、每行一个对象、JSON 数组或带缩进的整块 JSON
- **THEN** 界面列出的容器行一种不多一种不少,字段也不缺

#### Scenario: CL-017 读不懂的行要说清是哪一行
- **WHEN** wslc 的输出里有一行不是有效的容器 JSON
- **THEN** 错误条读得到"第几行"和那行的原文片段
- **AND** 说的是"容器"这类数据读错了,不是含糊的一句"解析失败"

#### Scenario: CL-018 错误条丢掉样板话
- **WHEN** `wslc list` 以非 0 退出码失败,stderr 里写着错误描述与`错误代码:`一行
- **THEN** 错误条读得到那句错误描述与`错误代码:`那一行
- **AND** 读不到"如果此错误是意外错误,请考虑搜索现有问题或…"这句样板话

#### Scenario: CL-019 stderr 是空的也要有话
- **WHEN** `wslc list` 非 0 退出但 stderr 一个字都没有
- **THEN** 错误条读得到"wslc 命令执行失败。",不是一句空话

#### Scenario: CL-020 读失败不冲掉已经看见的列表
- **WHEN** 上一次刷新成功、这一次失败
- **THEN** 列表还是上一次那几行,一行的内容都没被清空
- **AND** 错误条同时挂出来,下次刷成功它就没了

#### Scenario: CL-021 没装 wslc 时告诉用户怎么办
- **WHEN** 本机找不到 `wslc.exe`
- **THEN** 错误条读得到要安装并启用 WSL 3,或者设置环境变量指到 `wslc.exe` 的完整路径
- **AND** 应用不崩、不弹框,界面其余部分照常

#### Scenario: CL-022 找 wslc 的顺序
- **WHEN** 环境变量指向一份 wslc,`%ProgramFiles%\WSL\wslc.exe` 又放着另一份
- **THEN** 三份候选里取第一个真实存在的,顺序是环境变量 > `Program Files\WSL` > PATH(环境变量只要设了就直接用它,见 CL-023)
- **AND** 用的是哪一份在设置页的关于卡片里也读得到(见 `settings.md`)

#### Scenario: CL-023 环境变量指错了路就当没装
- **WHEN** `WSLD_WSLC_PATH` 有值,但那个路径上没有文件
- **THEN** 应用不回头用 `Program Files\WSL` 或 PATH 里的那一份,而是按"没装"处理
- **AND** 错误条读得到 CL-021 那句,里面点明了这个环境变量的名字(设错了的人能自己发现)
