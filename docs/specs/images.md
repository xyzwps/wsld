# images

## Purpose
镜像页那一列镜像:从 `wslc images --format json` 读进来、一行报哪几样、搜索与排序与汇总怎么说。
两个动作(拉取 / 删除)在 `image-actions.md`(IA),拉取途中的实时进度在 `pull-progress.md`(PP),
镜像源改写与拉后改名在 `registry-mirror.md`(RM),左侧导航与窗口几何在 `shell.md`。

### Requirement: 摆出来的就是本机有的镜像
数据只来自 `wslc images --format json` 这一条命令;字段名首字母大写、数字写成字符串、
同一镜像 ID 可以占好几行,这些都是 `wslc` 的实际形态(依据见 `docs/notes/wslc-images.md`)。
应用不自己拼数字,也不按 ID 猜该合并谁。

#### Scenario: IM-001 停在镜像页就自动加载一次
- **WHEN** 本机有镜像,切到「镜像」页
- **THEN** 不用点任何东西,本机的镜像逐条摆出来
- **AND** 每一条与手敲 `wslc images` 看到的行一一对应,不多不少

#### Scenario: IM-002 一行报的只有这几样
- **WHEN** 停在「镜像」页看任一行
- **THEN** 读得到 `仓库名:标签`、大小、被引用情况
- **AND** 下面那行小字读得到短 ID 与创建时间,形如 "ID aaef90e06523 · 创建 2026-05-13 10:21"

#### Scenario: IM-003 引用数写成字符串还是写成数字都读得出
- **WHEN** 同一个镜像, wslc 一次把它写成 `"Containers":"2"`,一次写成 `"Containers":2`
- **THEN** 两种写法下那一行都读得到 "被 2 个容器引用"

#### Scenario: IM-004 引用数读不成数字时按没人用说
- **WHEN** 那一行的引用数写着 `N/A`、写着空串,或干脆没有这个字段
- **THEN** 那一行读得到 "未被容器引用"
- **AND** 界面不说解析失败,这一行也不消失

#### Scenario: IM-005 没有标签的镜像有自己的说法
- **WHEN** 本机有一个仓库名与标签都写着 `<none>` 的镜像
- **THEN** 那一行读得到 "无标签 · <短 ID>",不是把 `<none>` 直接甩给用户
- **AND** 只有仓库名而标签是 `<none>` 时,这一行说的就是这个仓库名本身,删除走的也是它

#### Scenario: IM-006 同一镜像的两个标签占两行
- **WHEN** 一个镜像在本机有两个标签(打过 `wslc tag` 之后的常态)
- **THEN** 列表里是两行,名称分别是两个 `仓库:标签`
- **AND** 这两行的短 ID 与被引用数一模一样,界面不按 ID 把它们并成一行

#### Scenario: IM-007 无标签镜像删的是它自己
- **WHEN** 在无标签那一行上发起删除
- **THEN** `wslc` 那侧收到的是 `rmi <镜像 ID>` 这一条,不是 `rmi <none>:<none>`
- **AND** 删除动作本身的规矩归 IA

#### Scenario: IM-008 创建时间与大小按人能读的样子写
- **WHEN** wslc 把创建时间写成 `2026-05-13 10:21:49 +0800 GMT+8`
- **THEN** 那一行读得到本地时刻 `2026-05-13 10:21`,大小照 wslc 给的写法读(如 `4.45MB`)
- **AND** 这段时刻解析不动时,那一行把 wslc 写的话原样显示出来,不空着也不报错

#### Scenario: IM-021 只发那一条读镜像的命令
- **WHEN** 这一页去读镜像列表(进入页面或点刷新)
- **THEN** `wslc` 那侧收到的命令行是 `images --format json`,不多发一条、也不带 `-a` 之外的别的写法

### Requirement: wslc 的输出形态怎么变都读得进
无镜像时输出是空的;正常输出是每行一个对象;同一批数据也可能被排成 JSON 数组或带缩进的整块。
读不懂的行要说清是哪一行,而且说的是「镜像」(依据见 `docs/notes/wslc-images.md`)。

#### Scenario: IM-009 空输出不是错误
- **WHEN** 本机一个镜像都没有, wslc 一个字都没输出
- **THEN** 界面不出现错误条
- **AND** 汇总位置读得到 "本机还没有镜像"

#### Scenario: IM-010 排版变了行也还在
- **WHEN** 同一批镜像被 wslc 排成每行一个对象、JSON 数组或带缩进的整块 JSON
- **THEN** 界面列出的行数与字段一种不多一种不少

#### Scenario: IM-011 读不懂的行要说清是哪一行
- **WHEN** wslc 的输出里有一行不是有效的镜像 JSON
- **THEN** 错误条读得到是第几行,以及那一行的原文片段
- **AND** 说的是「镜像」这类数据读错了,不是含糊的一句"解析失败"

#### Scenario: IM-012 读失败不冲掉已经看见的列表
- **WHEN** 上一次加载成功,这一次 `wslc images` 以非 0 退出码失败
- **THEN** 列表还是上一次那几行,一行的内容都没被清空
- **AND** 错误条同时挂出来,说的是 `wslc images` 这条命令没成,下次加载成功它就没了

### Requirement: 找一个镜像不用翻页
搜索只在已经读回来的数据里挑,一次进程都不起。

#### Scenario: IM-013 输入即过滤
- **WHEN** 在搜索框(提示语写着 "搜索仓库名 / 标签 / ID")里逐字输入某镜像的仓库名、标签或 ID 的任一片段
- **THEN** 列表立刻只剩匹配的那些行
- **AND** 匹配不区分大小写,也不要求从头开始

#### Scenario: IM-014 过滤不惊动 wslc
- **WHEN** 输入搜索词,又把搜索词删干净
- **THEN** `wslc` 那侧一条命令都没收到
- **AND** 列表回到当前全量的行,顺序不变

#### Scenario: IM-015 一个都没匹配上
- **WHEN** 搜索词把每一行都筛掉了
- **THEN** 读得到 "没有匹配的镜像",界面不出现错误条

### Requirement: 顺序与汇总说的是全量,不是眼前这几行
默认顺序只为"清理时先看有用的"服务: 被引用的在前。汇总那三个数与搜索过滤无关
(实测引用数并不代表运行状态,依据见 `docs/notes/wslc-images.md`)。

#### Scenario: IM-016 被引用的排前面
- **WHEN** 本机既有被容器引用的镜像,也有没人引用的镜像
- **THEN** 被引用的那些行排在前面
- **AND** 同一档内按仓库名、再按标签排,都不区分大小写

#### Scenario: IM-017 汇总报的是全量
- **WHEN** 本机有 N 个镜像、其中 M 个有标签、K 个正被容器引用
- **THEN** 读得到 "共 N 个镜像 · M 个有标签 · K 个正被容器引用"
- **AND** 输入搜索词只剩几行时,这三个数不变

#### Scenario: IM-018 一个镜像都没有时换成一句人话
- **WHEN** 本机一个镜像都没有
- **THEN** 汇总位置读得到 "本机还没有镜像",不出现 "共 0 个镜像 · 0 个有标签 · …" 这种算式

### Requirement: 停在页面上不会自己变
镜像不像容器那样起起停停,所以这一页**不做自动轮询**: 待着不动就一条命令都不发,
底部那句说明把这件事写在界面上;手动刷新那颗键的规矩归 IA。

#### Scenario: IM-019 外部拉了镜像,这一页不动
- **WHEN** 应用开着、停在「镜像」页,在另一个终端里 `wslc pull` 拉下一个新镜像
- **THEN** 列表不自己变, `wslc` 那侧也没收到新的 `images` 请求

#### Scenario: IM-020 那句说明看得见
- **WHEN** 停在「镜像」页,谁都不点
- **THEN** 页面底部读得到 "· 镜像不会自动变化,拉取或删除后会自动更新列表"

#### Scenario: IM-022 刷新没读完不叠加下一次
- **WHEN** 一次读取还在进行,又点了一次「刷新」(或手动刷新与别处来的刷新撞上)
- **THEN** 这一轮被直接跳过,`wslc` 那侧不会同时挂着两条 `images`,界面不闪断
