# 拉取实时进度(伪终端)的依据

## 这个功能存在的唯一理由

`wslc pull` 在普通重定向管道下**不会**逐行输出:实测把 stdout 重定向到文件后,前 12 秒始终 0 字节,
进程退出那一刻才一次性出现全部 45 行。所以功能 004 当年只能退而求其次报"正在拉取 … · 已等待 N 秒"。
而拉取慢的时候(实测 60 秒起步、偶尔一直卡在 `Pulling fs layer`)用户看到的确实只是一个转圈,
完全无从判断"是在下载、在解压、还是已经死了"。

分层进度本身 wslc 已经算好了 —— 它只是没往非终端的输出里写。把子进程挂进 Windows 伪终端(ConPTY),
骗过它"我在不在终端里"这个判断,就能拿到和用户在 PowerShell 里手敲 `wslc pull` 看到的同一张屏幕,
不用应用自己猜百分比。

## 实测表

| 主题 | 实测结论 |
|---|---|
| 非终端下不流式 | 普通重定向管道:`wslc pull` 到进程退出才一次性冲刷全部行;ConPTY:3–5 秒出第一帧,之后按 wslc 自己的节奏(~15–20 秒一次)原地刷新分层行 |
| 进度是"原地回写" | 每个分层固定占一行,wslc 用绝对定位(CUP)+ 擦除(ED/ECH)把新状态盖在同一行上,**不是无限追加**。所以必须维护一个屏幕模型(`VtScreenTracker`),按"读到第几行"来算是错的 |
| 分层行形态 | `<12位以上十六进制>: <状态>`;字节写作 `544.5kB` / `1.073MB` / `2.14GB`(**1000 进制**,小数位会变),解压阶段写作 `Extracting 5.5MB/27MB`(分母是这一层的全量)。`24.04: Pulling from library/ubuntu` 是头行,`Digest:` / `Status:` / 完整引用是收尾三行,都不算层 |
| 终态只有两种 | `Pull complete` 和 `Already exists` 才算一层完成;`Download complete` 只是下载完了、还没解压,`Verifying Checksum` 是瞬时事件且不带字节 |
| `Download complete` 不再报字节 | **真机坑**:某层进入 `Download complete` 后那一行不再带字节数。只按当前帧求和的话,"已下载"会从 1.6 MB 退回 545.6 kB 甚至归零 —— 界面上数字倒退比不显示更糟。所以每层记历史最大值(台账),总量只增不减。详见 dev-notes 第 30 条 |
| 父进程标准句柄会盖掉伪控制台 | 见 dev-notes 第 29 条(从管道/测试宿主里起进程时子进程根本没挂上 ConPTY,表现就是"只有转圈") |
| 提前关输入写端 = 广播 Ctrl+C | 见 dev-notes 第 28 条(输入写端必须一直开着,直到真的取消或结束) |
| stdout 与 stderr 合成一路 | 伪终端里两者不分家:整块屏幕当 stdout 交给 `WslcPullLog` 解析(`Status:` 行还在里面);错误横幅只取"不是分层进度"的那些行,否则几十行 `Downloading…` 会把真正的报错淹没 |
| 重复拉已存在的镜像 | 全程 ~2 秒,屏幕只有头行与 `Already exists` / 收尾三行,没有字节数 —— 汇总行这时不该占位 |
| 取消 | 按整树终止 `wslc` 进程,面板当场收起、提示"已取消拉取 …"(半截镜像与残留进程的事见 `wslc-images.md`) |
| 网络差的时候 | 一个层可以几十秒停在 `Pulling fs layer`、"已下载 0 B"(debian:12-slim 实测 54 秒后才开始报字节)。百分比这时候确实算不出来,但"卡在哪一层、已经等了多久"本身就是能用的反馈 |
| 界面刷新次数 | 一帧里 wslc 会连着写好几个转义块;内容与上一次完全相同的帧直接丢掉,不然界面会白抖 |

真机走查对照(Windows 11 + wslc 3.0.1):`docker.1ms.run/library/nginx:1.27-alpine` 上屏 9 行分层状态,
`Waiting` / `Download complete` 随刷新原地变化;`docker.1ms.run/library/debian:12-slim` 前 54 秒停在
`Pulling fs layer` / "已下载 0 B",54 秒后变成 `Downloading 532.5kB` / "已下载 532.5 kB"。

## 汇总数字的算法依据

- `TotalLayers` = 见过的分层数(头行 / `Digest:` / `Status:` / 引用行都不算);
- `DoneLayers` = 状态以 `Pull complete` 或 `Already exists` 开头的层数;
- `DownloadedBytes` = 每层**历史最大**字节数之和 —— 单调不减,某层不再报字节数也仍然算在里面;
- 字节按 1000 进制格式化成 `544.5 kB` / `1.1 MB` / `2.1 GB`,与 wslc 自己的写法同风格;
- 层数为 0(manifest 还没拿到)时汇总为空,界面上这一行不占位置;
- 行数只随**层数**增长、不随刷新次数变长(一条进度 = 一个分层的最新状态);
- 台账属于**一次拉取**:开始新操作时进度行、去重用的"上一次推送"、每层字节台账三样一起清,
  少清第三条,第二趟的"已下载"会从上一趟的数字接着往上涨。

## 降级与边界

- ConPTY 起不来时**静默退回普通管道路径**,结束时把全部行一次性交给同一个回调:
  降级只影响"中途有没有反馈",不影响拉取结果,不弹错误框。理论上只有 Windows 10 1809 以前
  或被安全软件拦住 conhost 才会发生。
- **刷新节奏由 wslc 决定**(实测 ~15–20 秒一帧),应用不造"假进度"。想要更细的百分比得 wslc 自己给总字节数,
  目前它只给"这一层目前下了多少"。
- **"已下载"是各层"见过的最大字节数"之和,不是流量统计**:`Extracting 5.5MB/27MB` 里的分母会被当成
  这一层的全量计入。跨层平均值、速率这类需要时间序列的东西不做。
- **错误横幅靠"去掉分层进度行"来提纯**:极端情况下报错信息长得像分层行(`<十六进制>: …`)会被滤掉,
  但整块屏幕仍照常进 stdout 参与结果解析。
- 这一版只把 `pull` 接进伪终端;屏幕还原与伪终端会话本身是通用的,以后给别的长命令加实时进度可以直接复用。
- 取消必须报成"已取消",不能被报成命令失败(见 dev-notes 第 17 条)。
