# 配置读写的依据

## 文件与字段

位置:`%LOCALAPPDATA%\wsld\settings.json`(关于卡片里要显示完整路径,方便用户去找它)。
枚举序列化成**可读名字**,不是数字。

| 字段 | 含义 | 默认值 |
|---|---|---|
| `Theme` | 跟随系统 / 浅色 / 深色 | 跟随系统 |
| `Language` | 跟随系统 / 简体中文 / English | 跟随系统 |
| `RegistryMirror` | 镜像站地址,空串 = 不使用镜像源 | 空串 |
| `RenameMirrorPull` | 拉取后把镜像改名回用户输入的名字 | `true` |

`AppSettings` 新增字段**必须给默认值**,老配置文件才读得动 —— 老文件里没有这两个字段时走默认值
(不使用镜像源 / 改名开着),照样读。

## 容错档位

| 情形 | 约定行为 |
|---|---|
| 文件不存在 | 返回默认值(跟随系统 + 跟随系统),**绝不抛异常** |
| JSON 坏掉 | 同上 |
| 没有写权限 / 写失败 | 只是"没存住",界面照常工作,不弹错误 |
| 带 UTF-8 BOM | 必须读得动 → 见 dev-notes 第 22 条(带 BOM 时兜底 `catch` 会把它表现成"设置被莫名其妙重置") |
| 带注释、带尾逗号、属性名大小写不同、将来新增的未知字段 | 都要容忍 |
| `"RegistryMirror": null` | setter 把 `null` 归一成空串,null 不能漏进对象 |

设计前提:设置读坏了不能把应用启动搞崩,所以外面包一层兜底。dev-notes 第 22 条顺带留的提醒同样适用于这里 ——
默认值本身要无害,而且最好只兜底**读**,不要顺手把写失败也一起吞成"成功"。

## 取舍:存原样输入,规范化用时现算

`RegistryMirror` 存的是用户**原样输入**的那串(只去首尾空白),规范化每次使用时现算。
理由:用户回到设置页看到的还是自己写的东西,不会被应用"改写"掉。
实测:填 `https://Docker.1ms.run/` 后 `settings.json` 里就是 `"RegistryMirror": "https://Docker.1ms.run/"` ——
带协议、原大小写,同时 `"RenameMirrorPull": true`。

落盘时机:设置页里打字时只刷预览、**不落盘**(每按一个键写一次设置文件没意义);
回车 / 焦点离开 / 离开本页三种方式都会落盘,与"选中即生效"的既有约定对齐。
主题和语言是选中即生效、即存盘,没有"保存"按钮 —— 少一步,也免得改了没存。

## 镜像源地址的合法性判定(`RegistryMirrorPolicy.TryNormalize`)

- 容忍用户连协议一起粘贴:`https://docker.1ms.run/`、结尾斜杠都行 —— 协议与首尾空白被剥掉;
- **主机名不区分大小写**,存进规范化结果时转小写;
- 允许带端口(`mirror.example.com:5000`)和路径前缀(`/v2/private`)—— **路径部分原样保留大小写**,
  只有主机名转小写;
- 判"像不像注册地址":含空白、或者主机段既没有点也没有端口又不是 `localhost` → 无效;
- 无效时**不静默丢弃**:设置页在预览位置显示一句提醒("这一串不像注册地址:应写成 registry.example.com,
  可以带端口或路径前缀。"),行为等同"不使用镜像源";
- 空串 = 不使用镜像源。

改写规则本身(哪些引用会被换成 `<mirror>/…`)见 `registry-mirror.md`。
