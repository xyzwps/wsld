# 界面外壳的实测依据

覆盖顶栏 / 标题栏接管、主题换皮、图标按钮约定、页签与导航那几处"只有真机才知道"的形态。
词条相关见 `i18n-keys.md`,布局类崩溃与量宽类误判见 dev-notes。

## 接管系统标题栏

| 主题 | 实测结论 |
|---|---|
| 接管方式 | `AppWindow.TitleBar.ExtendsContentIntoTitleBar = true` + `SetTitleBar(元素)` 即可;`SetTitleBar` 给的那个元素**整块成为拖拽区** |
| 系统按钮留白 | `TitleBar.RightInset` 是**物理像素**,要除以 `XamlRoot.RasterizationScale` 才能当 XAML 的 DIP 用 |
| 最大化时的额外内缩 | 窗口最大化时系统内容区还会**再内缩 8 DIP**,不留出来按钮会跑到屏幕外 |
| 系统按钮高度 | 顶栏加高到 46 DIP 后,必须同时设 `PreferredHeightOption = Tall`,否则最小化/关闭按钮靠上、自绘按钮居中,视觉上错位 |
| `Window` 根上的绑定 | 编译限制:`x:Bind` + 转换器无法在 `Window` 根元素上生成代码,顶栏和导航项的文案只能在代码里赋值 → 见 dev-notes 第 2 条 |
| 主题生效范围 | `Root.RequestedTheme` 设 Light / Dark / Default,`Default` 就是"跟随系统";但 `Window` 自身的底色**不跟 `Root` 变**,必须显式给 `Background`,否则浅色模式下导航区透出深色底、整片发黑 |

为什么重做顶条:原来是"系统标题栏 + 页面里再来一个大标题",两条标题叠在一起,窗口高度白吃掉一截,
深色模式下两条的颜色还不一致。

系统标题栏虽然被接管,`Window.Title` 仍然保持 `wsld` —— 任务栏和 UIA 还要靠它认窗口名。

## 主题:三档与"换皮要换全"

- 三档:跟随系统 / 浅色 / 深色,`Default` 就是"跟随系统",界面自己不做第二套判断;
  改完立即生效,不需要重启(生效范围那一条见上面的实测表)。
- 深浅其实是**三处独立的**:根元素的 `RequestedTheme`、`Window` 自己的底色、系统那三颗标题栏按钮的配色。
  少给一处就出现"浅色模式下导航区黑成一片",或者深色标题栏里按钮看不清。
- 顶栏那颗快切键**只在浅色 ↔ 深色之间来回**,切的是"当前实际呈现的那一档":主题是"跟随系统"而系统正深色时,
  点下去切到「浅色」这一档,而不是回到"跟随系统"。
- 快切键切完要把结果**同步回设置页的选中态**(已经存在的设置页要被通知重读),否则出现
  "界面已经是浅色,选项还停在跟随系统"。
- 验收口径:深色 / 浅色 × 中文 / 英文 四种组合逐页走查,每一页都读得清,没有"深底深字"或"浅底浅字" ——
  这一条只能真机看(见 `test-verification.md`)。

## 图标按钮

四套统一样式:`IconOnlyButtonStyle`(普通)、`AccentIconButtonStyle`(主操作)、
`DangerIconButtonStyle`(破坏性操作,红色图标)、`TitleBarIconButtonStyle`(顶栏扁平键);
图标码点集中在 `App.xaml` 的 `IconFont`(Segoe MDL2 Assets)。

为什么要换成图标:一行四个文字按钮("启动 停止 重启 删除")就把列表行撑满,换成英文更长
("Start / Stop / Restart / Delete"),日志页工具栏更是直接被右边缘裁掉。图标 + 悬停说明能把横向空间还回来。

**强制约定**:每个纯图标按钮必须**同时**提供 `ToolTipService.ToolTip` 和 `AutomationProperties.Name`,
且两者都走 Localizer —— 少一个就是"读屏软件念不出这是什么按钮"或"换语言后残留另一种语言"。
纯图标对读屏软件和鼠标键盘用户是灾难,所以这两项不是可选项。
镜像页的删除按钮在被"占用拒绝"过一次之后语义升级为强制删除,tooltip 要跟着状态变。

入口位置的取舍:列表行内只放"启动",停止 / 重启 / 删除放在选中该容器后的详情面板 ——
四个图标按钮挤在定宽的行里会把名字顶没,而点一行本来就会把它的详情打开。

## 页签与导航

- 固定数量、不可新建、不可关闭的两个页签(「详情 / 日志」)**不用 `TabView`**:
  Windows App SDK 2.5 上它自带一个"新建标签"的 + 按钮,`IsAddButtonVisible` 这个属性在该版本 XamlCompiler
  直接报 Unknown member,关不掉 → 见 dev-notes 第 44 条(含自建 RadioButton 页签的视觉态必须成对写)。
- 设置项放在 `NavigationView.FooterMenuItems`,与三个功能页分开;`IsSettingsVisible="False"`,
  免得框架自带的"设置"和自建的入口打架。
- 侧栏切换页面不丢各自的加载状态(页面实例常驻,不重复创建)。

## 宽度与防裁切

| 主题 | 实测结论 |
|---|---|
| ComboBox 的 UIA 矩形 | 把"下拉展开的占位"一起算进去:固定 150 DIP 的"行数"下拉,UIA 报 237×95;不给固定宽度时按内容要宽(实测英文 107 DIP、中文 124 DIP)。**判断"要不要限宽"只能看闭合状态的渲染截图** → 见 dev-notes 第 23 条 |
| "行数"下拉固定 150 DIP 的真正理由 | 中英切换时工具栏宽度不跳、且最长条目一定放得下(实测中文"最近 1000 行"、英文"1000 lines"),不是"不固定就会溢出" |
| 验收口径 | 1180×780 窗口下,中文和英文两种界面里:日志区"行数 + 显示时间戳 + 实时跟随 + 自动滚动"一整行、容器页与镜像页的行内操作按钮组都不被右边缘裁切 |

布局上"动作按钮一律 `Auto` 列、会变长的下拉放 `*` 列 + `MaxWidth`"这条约定与 `ToggleSwitch` 默认
`MinWidth=154` 的坑,见 dev-notes 第 18 条、第 23 条。
