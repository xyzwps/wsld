# `wslc run` 命令编排的依据

## 为什么要做这张表单

`wslc run` 一条命令动辄七八个选项,端口、挂载、环境变量还是可重复的。终端里手敲有三个实际成本:
拼错 `-p` 的格式要等容器起不来才发现;想换个端口就得从头再敲一遍;上一条命令躺在历史记录里,
想复用只能翻历史再改,改坏了还看不出来。所以把"写命令"变成"填表 + 一眼看到结果",
复制走的那条和就地执行的那条出自同一份数据,不存在"预览一个、执行另一个"两副面孔。
拼装顺序固定,同样一张表单项填得再乱,命令长相恒定,便于肉眼比对与 diff。

## 实测表

| 主题 | 实测结论 |
|---|---|
| 选项集合对得上 | `wslc run --help` 列出的"带值选项"全集与 `RunCommandBuilder.ValueFlags` 一致(含 `-e/-l/-m/-p/-u/-v/-w/-h` 的短形式与长形式别名) |
| 命令别名 | `wslc run` 与 `wslc container run` 都接受,读回时两种前缀都认 |
| `--pull` 的默认 | 真实默认是 `missing`。界面里的"默认"= **不下发这个选项**,让 wslc 自己的默认生效,而不是替用户写死一个 |
| `-d` 的输出 | 只有一行 64 位容器 ID(`wslc run -d --rm --name wslcd-012-smoke -p 18080:80 docker.1ms.run/library/nginx` 实测) |
| `--rm` | 容器停下即删除,`wslc list -a` 里查不到这个 name,**不需要应用补刀清理** |
| 裸镜像名 ≠ 本机镜像 | 本机镜像带着 `docker.1ms.run/library/` 前缀,敲 `nginx` 会解析到 docker.io 并去拉取,网络差时直接 `context deadline exceeded` / `E_FAIL` 失败 |
| 空行不参与拼装 | 加了一行没填 = 视同不存在,不会留下空的 `-p` / `-v` / `-e` |
| `-w` / `-u` 曾经漏发 | `Build()` 没输出工作目录与用户,界面填了却静默丢弃;而 `TryParse` 还会把它们读回来 —— 一来一回更难发现。已补进拼装顺序并加回归用例 |
| 样式贴错类型会当场崩 | 端口行的协议下拉框误贴文本框样式 → 点「添加端口」时 `XamlParseException`,整个应用退出(0xc000027b),而编译、打开页面、跑单测全都正常 → 见 dev-notes 第 37 条 |
| 剪贴板占用被误报成失败 | `Clipboard.Flush()` 抛 `0x800401D0`(别的进程正开着剪贴板)时内容其实已经可粘 → 见 dev-notes 第 38 条 |
| 下拉框选框空着 | 「拉取策略」用内联 `ComboBoxItem` + 绑定内容时,序号已选中但框里没字;候选项换成纯字符串即好 → 见 dev-notes 第 39 条 |

## 由实测直接定下来的做法

- **镜像候选列表一律用 `wslc images` 的完整引用**,不猜短名 —— 因为裸名不等于本机那个镜像。
  候选只是辅助:取不到(未装 wslc、命令失败)就留空,手打不受影响。
- 除"后台运行"默认勾上之外,**任何字段留空都不输出对应选项**;整行留空跳过该行。
- **就地执行**:默认后台运行,秒回容器 ID 并提示"可到「容器」页查看";取消勾选后台运行则容器输出逐行实时落到输出框。
  运行中可终止 —— **只终止本应用起的 `wslc` 进程**;容器若已经起来由 wslc 侧接管,要停容器请去「容器」页,
  本功能不假装能替用户"顺手把容器也停掉"。
- 失败时把 wslc 的报错原样呈现(去掉 wslc 自带的那句样板套话,见 `wslc-cli.md`),不让用户只看见一个"失败"。
- **长尾选项走原样透传、不校验**:`--mount`、`--ip`、`--cidfile`、`--network-alias`、`--stop-signal` 这些
  只进"其他参数";`TryParse` 认不出的选项也连同取值整段进其他参数(如 `--gpus all`、`--dns 8.8.8.8`、`--ulimit`、
  `--pull` 的非三个标准值)。有独立输入框的那几个选项才做逐项校验。
- **校验只到客户端这一层**:端口号、必填、整数这类能当场判定的会拦住,并且复制与就地执行都不放行;
  路径不存在、端口被占用、镜像拉不下来这些要 wslc 才知道的,照它的报错原文呈现。
- 读回命令时是**逐属性搬到现有表单对象上**(页面的绑定与监听都挂在同一个对象上),不是换新对象;
  剪贴板里没有文本、或读不懂(不是 `wslc run` 命令)各有各的提示,并且**不动**用户已经填好的内容。
- 执行历史只活一个会话(最近 100 条、连续同一条只记一次、按"按下执行"记录不问成败 ——
  跑失败了更要能找回),**不落盘**:它救的是"这条没跑对,我要接着改"的工作现场,不是档案;
  跨会话复用仍走剪贴板。
- `Windows` 盘符带冒号(`C:\data:/app:ro`)、带空格的值(引号包住)都要能读回来;
  `显示 → 读回 → 显示` 结果不变。
