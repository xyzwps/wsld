# wslc 日志侧实测

依据来源:本机 WSLC 3.0.1 实测。`wslc logs [选项] <container-id>`,别名 `wslc container logs`。
选项只有 `--details`、`-f/--follow`、`-n/--tail`、`-t/--timestamps`、`--since`、`--until`,
**没有 `--format json`**(通用错误形态见 `wslc-cli.md`)。

## 实测表

| 场景 | 实测结果 |
|---|---|
| `logs <运行中的容器>` | 退出码 0,stdout 是原始文本行(`log line 1 at 1791804984` …),行尾只有 LF |
| 用名称 / 短 ID / 长 ID | 都可以(`logs probe1`、`logs f47fdddf9219` 都是退出码 0) |
| `logs <已退出的容器>`(probe1) | **退出码 0 + 空输出**,不报错 |
| `logs <从未启动的容器>`(probe2,Created) | **退出码 0 + 空输出**,不报错 |
| `logs <不存在的容器>` | 退出码 1;stderr:`找不到容器 'nosuchcontainer'。` + `错误代码： WSLC_E_CONTAINER_NOT_FOUND` + 样板句 |
| `logs -n 3` | 退出码 0,只给最后 3 行 |
| `logs -n 1000000`(超出实际行数) | 退出码 0,不报错 |
| **`logs -n 0` / `-n -1` / `-n abc`** | 退出码 **1**;stderr 首行 `tail 选项值无效: 0` + 8 行 usage;**stdout 为空** |
| `logs -t` | 每行前缀 RFC3339 **UTC 纳秒** + 空格:`2026-10-12T11:34:46.874570304Z log line 146 at ...` |
| **`logs -f` 不带起点** | 会**先把全部历史冲出来**再持续追加 → "只看新行"不能只靠 `-f` |
| **`logs --since <epoch 秒>` / `--since <RFC3339>`** | 都接受;给未来时刻 → 退出码 0、零行输出(过滤确实生效) |
| **`logs -f --since <现在>`(容器已停止)** | 退出码 0、**一行历史都没有** → `--since` 连 `-f` 开头那次冲刷一起过滤 |
| `logs -f <已停止的容器>` | 立刻结束,退出码 0,stdout / stderr 全空(不报错也不提示) |
| **跟随时容器被停止** | ≤2 秒内 wslc 自己退出,退出码 0,stderr 空,**没有任何"容器已结束"的提示行** |
| 跟随途中结束 wslc 进程 | 用整棵进程树终止,之后 `Get-Process wslc` 为 0 个,无残留 |

## 这四条是做法的直接依据

- **空输出 + 退出码 0 是正常语义**("这容器没打印东西"),界面不能报成错误。
  命令行里它和"命令失败"长得一样,很容易误判成"日志被清掉了" —— 所以"这个容器没有输出"和"读取失败"
  必须明确区分开。
- **参数非法也是退出码 1、文案走 stderr,还带 8 行 usage 噪音**。界面不该把这 8 行甩给用户,
  所以应用在发命令之前自己校验(容器标识为空、查看模式行数 < 0 或 > 100000 都不放行)。
- **`-t` 给的是 UTC 纳秒串**,又长又难读 → 界面转成本地 `HH:mm:ss.fff`,解析不了就原样保留
  (行内其余内容不动;没开启时间戳时绝不改动行内容,哪怕它长得像时间戳)。
- **跟随时会"自然结束"且不留原因** → 界面自己负责说明"实时日志已结束(容器多半已停止)"。

## 实时日志必须有起点

`-f` 单独用会把全部历史冲出来,那就不是"实时日志"了。实测 `--since` 能把那次开头冲刷一起过滤掉,
所以实时读法的命令形态是 `logs -f [-t] --since <Unix 秒> <容器>`,**不带 `-n`** —— 起点之后的行不该再被行数截断。
`--since` 缺失或非正时进程一次都不启动(dev-notes 第 44 条末尾顺带记过这条实测)。

## 终止跟随

终止走整棵进程树,已经上屏的行不清空,容器里不留下任何东西(实测)。
另一个必须记住的形态:被终止的 `wslc` 常带着退出码 `-1` 自己退场,竞速下容易被判成"命令失败" ——
见 dev-notes 第 17 条。**取消就是取消,不能报成失败。**

`logs -f <已停止的容器>` 立刻结束且毫无提示(退出码 0、输出全空),只会让人以为按钮坏了 ——
所以"实时"这个入口对不在运行的容器直接灰掉,悬停说明写清楚"看不了实时日志,要翻旧日志请用查看日志"。

## 为什么是两种读法,而不是一个日志页

命令行做这件事有三处别扭(实测):得先 `wslc list` 抄名字、`-n` 与 `-t` 自己记、想持续观察就得开个
终端挂着 `-f`。而 `logs -f` 不带起点会先把**全部历史**冲出来 —— "盯新行"和"读历史"在 CLI 里是同一条命令
的不同参数,在界面上却是两件不同的事:盯新行时不该先把几万行历史冲出来,读历史时不该不知不觉挂着一个进程。
所以界面上给两个入口、各发各的命令(册子 LG-001 与 LG-002)。
